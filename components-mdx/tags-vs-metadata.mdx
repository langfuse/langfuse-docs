## Tags vs. metadata [#tags-vs-metadata]

Tags and metadata both let you attach extra information to traces and observations, but they serve different purposes and have different performance characteristics.

**Use tags** for a small, known set of categorical labels that you want to filter or group by — for example the environment, the feature or API used, or a manual QA flag. Tags support **breakdown/group-by** in [Custom Dashboard](/docs/metrics/features/custom-dashboards) widgets, so you can chart metrics broken down by tag. Because tags are not indexed in the underlying storage, filtering by tag scans the full column, and the tag picker and other tag-list views in the UI only display a bounded number of distinct values. This works well for dozens to a few hundred distinct tags, but a use case that needs thousands of distinct values (for example, one tag per customer) will run into UI and query-performance friction well before hitting any hard limit. For that kind of high-cardinality data, use metadata instead.

**Use metadata** for arbitrary key/value data, including high-cardinality values such as customer IDs, request IDs, or other identifiers you mainly want to look up or filter on. Metadata keys and values are indexed for efficient equality lookups, so filtering traces or observations by a specific metadata key/value pair remains efficient even with a very large number of distinct values. The trade-off today is that metadata can only be used to **filter** dashboard widgets, not as a breakdown/group-by dimension — you can narrow a widget to `metadata.customer_id = "123"`, but you can't yet chart a metric broken down by every distinct metadata value. Using metadata as a breakdown dimension is an open, tracked feature request ([GitHub issue #12614](https://github.com/langfuse/langfuse/issues/12614)) without a committed timeline.

In short: reach for tags when you need dashboard breakdowns over a manageable set of categories, and for metadata when you need to store or filter on high-cardinality or free-form data.

# Advent analytics

All explicit events use the existing website PostHog client and consent handling. The prefix is `advent:`. No separate client, identifiers, or consent settings are introduced. Events are also visible locally at `/advent?day=8&adventDebug=1` with **Copy diagnostics** or `window.__adventDebug.report()` in the console. Debug reports stay local; screenshots, shader compiler messages, and raw errors are not sent to PostHog.

Every event includes `schema_version`, `mode`, `motion`, `stage`, `slop`, `environment`, and `debug`. Filter production analysis to `environment = production` and `debug = false` to exclude preview testing.

| Events                                                              | Additional properties                                                                                   | Purpose                                                                               |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `viewed`, `started`, `calendar_ready`                               | `unlocked_day`, `system_reduced` on viewed                                                              | Entry funnel                                                                          |
| `audio_started`, `audio_failed`                                     | `success`, `state` on started                                                                           | Audio activation failures                                                             |
| `motion_changed`                                                    | `preference`, `system_reduced`                                                                          | Explicit full/calmer effects choice                                                   |
| `mode_selected`, `mode_arrived`                                     | `target_mode`, `duration_ms` on arrival                                                                 | Mode exploration and completion                                                       |
| `door_hovered`                                                      | `day`                                                                                                   | Discovery, once per door per page visit                                               |
| `door_selected`                                                     | `day`, `locked`, `input`                                                                                | Door intent, including locked attempts                                                |
| `door_viewed`, `door_left`                                          | `day`, `duration_ms` on left                                                                            | Actual content exposure and dwell time                                                |
| `door_navigated`                                                    | `day`, `from_day`                                                                                       | Previous/next navigation                                                              |
| `link_clicked`                                                      | `kind`, `destination`, `day`                                                                            | Feature, share, social and navigation clicks; destination excludes query and fragment |
| `slop_changed`, `volume_changed`                                    | `value`, `level` or `muted`                                                                             | Final setting in each two-second interaction window                                   |
| `snowball_thrown`, `snowball_impact`, `snowman_hit`, `reindeer_hit` | `count`, `power` or `level` where applicable                                                            | Play counts in two-second batches; sum `count`, not event count                       |
| `snowman_completed`                                                 | Common properties                                                                                       | Easter egg discovery                                                                  |
| `transition_started`                                                | `transition`, `renderer`, door `day`; door `setup_ms`, `pixels`                                         | Animation actually started                                                            |
| `transition_skipped`                                                | `transition`, `reason`, door `day`                                                                      | Unavailable Canvas                                                                    |
| `transition_finished`                                               | `transition`, `outcome`, `renderer`, `frames`, `frame_p95_ms`, `slow_frames`; door `duration_ms`, `day` | Completion, explicit skip, failure, rendering cost                                    |
| `renderer_fallback`, `capture_failed`                               | `transition`, door `day`; fallback `reason`, `renderer`                                                 | Runtime GPU/capture issues                                                            |

Useful analyses: `viewed → started → calendar_ready → door_viewed → link_clicked` funnel; unique viewers by day; share-click conversion; mode and Slop adoption; sum of snowball counts; median door dwell; transition outcome and p95 frame interval by device/browser and renderer. `frame_p95_ms` measures intervals of the capped 30 fps animation loop, not total browser FPS. Initial Canvas fallback is identified by `transition_started.renderer`; a context lost during flight produces `renderer_fallback` as well.

Diagnostics and analytics are observational: blocked PostHog, a failed clipboard write, slow capture, or unavailable WebGL cannot prevent the calendar opening. Start always runs an animated journey by default, regardless of the OS motion preference. The optional Calmer effects setting uses stationary frost and less camera travel, while preserving transitions and their sound timing. Explicit choices persist for this site. Hardware hints and observed frame timing reduce rendering cost without skipping the journey.

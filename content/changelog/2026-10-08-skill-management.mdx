You can now manage agent skills in Langfuse, from editing instructions to understanding how agents use them. Keep `SKILL.md`, reference documents, and scripts together in a versioned skill.

Share a consistent set of skills across your agents, test revised instructions with a staging label, or inspect which supporting files an agent loaded during a run.

## Edit and version skills

Create a skill in the UI or import existing files, folders, or ZIP archives. Edit instructions and supporting files, compare changes against a saved version, and publish a new version with a note describing the update.

Use labels such as `production` and `staging` to choose which version your agents receive. Saved versions remain immutable, so you can move a label back to an earlier version when needed.

## Install skills with the CLI

Open **Skills → Install with CLI** to generate commands for your skills and agent workspace. You can install a skill by name, select all skills with a tag, or pin a saved version from its detail page.

The Langfuse CLI is in beta and requires Node.js 20 or later. Run these commands in your local project directory:

```bash
npm install -g @langfuse/cli@1.3.0-beta.0
```

Get your project's public and secret keys from **Settings → API keys**, then configure the CLI in your current terminal session:

```bash
export LANGFUSE_PUBLIC_KEY='pk-lf-...'
export LANGFUSE_SECRET_KEY='sk-lf-...'
export LANGFUSE_HOST='https://your-langfuse-host'
```

Replace the placeholders with your project credentials and Langfuse deployment URL. If you already set `LANGFUSE_BASE_URL`, update it to the same URL.

Install a skill following a label, pin an exact version, or install every skill with a tag at the chosen label:

```bash
# Follow the production label when updating.
langfuse skills install 'refund-policy' --label='production'

# Pin an immutable version.
langfuse skills install 'refund-policy' --version 3

# Install every skill tagged customer-support at its production label.
langfuse skills install --tag='customer-support' --label='production'
```

Skills install into `.agents/skills` by default. Add `--directory='.claude/skills'` for Claude Code or `--directory='.cursor/skills'` for Cursor. Each skill selected by a tag must have the chosen label.

Commit `langfuse-skills-lock.json` to share the selection with your team. Updates use the saved directories and follow saved labels; pinned versions stay fixed:

```bash
langfuse skills update
```

Run `langfuse skills install` without arguments to reinstall the exact locked versions.

## Use skills from the SDK

SDK support is still in development. The examples below reflect the current local SDK API.

The JavaScript/TypeScript SDK lets you resolve skill versions and fetch their instructions and supporting files. Each manifest pins an immutable version, so moving a label does not change the files read during an agent run.

### Use skills in memory

For example, [Mastra's inline skills](https://mastra.ai/docs/skills) let you pass instructions and reference files directly to an agent. The example below fetches `SKILL.md` and every `references/` file from the pinned Langfuse version, then creates an in-memory skill for Mastra's native skill tools. It supports skills made up of instructions and references.

This example imports your existing configured Mastra instance from `./mastra`. Set up Mastra's `Observability` and `OtelBridge` with a `LangfuseSpanProcessor` using the [Langfuse OpenTelemetry setup](/docs/observability/sdk/overview). Registering the agent connects it to that tracing setup; `propagateAttributes({ skillsAvailable: manifests }, ...)` attaches the available skill names and versions to its traced generations. Successful instrumented skill tools supply the resource loads; fetching files into memory only prepares the skill.

```typescript
import { LangfuseClient, type SkillManifest } from "@langfuse/client";
import { propagateAttributes } from "@langfuse/tracing";
import { Agent } from "@mastra/core/agent";
import { createSkill, type InlineSkill } from "@mastra/core/skills";
import { mastra } from "./mastra";

const langfuse = new LangfuseClient();
const manifests = await langfuse.skills.listManifests({
  names: ["refund-policy"],
  label: "production",
});
const skills = await toMastraSkills(manifests);

const agent = new Agent({
  id: "support-agent",
  name: "Customer support agent",
  model: "anthropic/claude-sonnet-5-5",
  instructions:
    "Use the relevant skill and read its references before answering.",
  skills,
});
mastra.addAgent(agent);

const result = await propagateAttributes(
  { skillsAvailable: manifests },
  () =>
    agent.generate(
      "Use refund-policy to draft a reply to a customer requesting a refund.",
      { maxSteps: 10 },
    ),
);
console.log(result.text);

async function toMastraSkills(
  manifests: ReadonlyMap<string, SkillManifest>,
): Promise<InlineSkill[]> {
  return Promise.all(
    Array.from(manifests.values(), async (skill) => {
      const markdown = await langfuse.skills.getFileContent(skill, "SKILL.md");
      const references = Object.fromEntries(
        await Promise.all(
          skill.files
            .filter((file) => file.path.startsWith("references/"))
            .map(async (file) => [
              file.path.slice("references/".length),
              await langfuse.skills.getFileContent(skill, file.path),
            ]),
        ),
      );
      return createSkill({
        name: skill.name,
        description: skill.description,
        instructions: markdown.replace(/^---\r?\n[\s\S]*?\r?\n---(?:\r?\n|$)/, ""),
        references,
      });
    }),
  );
}
```

### Use installed skills with Claude Agent SDK

For agents that read skills from disk, install them with the CLI:

```bash
langfuse skills install 'refund-policy' --label='production' --directory='.claude/skills'
```

The Node.js helper reads your installed skill directories and CLI lockfile. With [Claude Agent SDK tracing configured](/integrations/frameworks/claude-agent-sdk-js), attach the available skills and their resolved versions to your agent run:

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";
import { readAvailableSkills } from "@langfuse/otel/skills";
import { propagateAttributes } from "@langfuse/tracing";

const skillsAvailable = readAvailableSkills({ dir: ".claude/skills" });

await propagateAttributes({ skillsAvailable }, async () => {
  for await (const message of query({
    prompt: "Use refund-policy to draft a reply to a customer requesting a refund.",
    options: {
      cwd: process.cwd(),
      settingSources: ["project"],
      skills: ["refund-policy"],
      allowedTools: ["Skill", "Read"],
    },
  })) {
    if (message.type === "result" && message.subtype === "success") {
      console.log(message.result);
    }
  }
});
```

Both examples require a `refund-policy` skill with a `production` label. The Mastra example requires your Langfuse project API credentials, `@mastra/core`, Node.js 22.13 or later, and `ANTHROPIC_API_KEY`. The Claude Agent SDK example requires the skill installed in `.claude/skills`, your tracing setup, and Claude Agent SDK authentication. Installing or fetching files does not record agent use; actual loads come from successful instrumented agent tools.

## See how agents use skills

With supported tracing integrations, record which skills were available and which files the agent loaded. An observation's **Attributes** tab shows **Available skills** and **Loaded resources**, including skill names, resolved versions when known, and loaded file paths.

Use custom dashboards to count how often skills were available and how often agents loaded their resources. Filter by skill name and break down resource loads by skill and file. Availability counts once per generation and skill; resource-load counts include repeated reads.

To get started, open **[Skills](https://cloud.langfuse.com/project/~/skills)** in your project sidebar.

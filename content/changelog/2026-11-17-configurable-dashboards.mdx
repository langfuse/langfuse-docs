Build charts directly in your dashboard. Start with a familiar preset, change what it measures, and compare several populations in one widget. Add text to explain what your team should take away.

- Compare observations containing `metadata.abc` with observations containing `metadata.bbc`, as two named bars.
- Plot p50 and p90 together, choose a custom percentile, or calculate the share of observations with errors.
- Combine a quality overview with explicit score targets, distribution charts, and notes explaining how to read them.

## Two metadata keys, two series

Each query defines a population with its own source, measures, and filters. Metrics and breakdown groups become the chart series. A second query lets you compare a different population.

| Series  | Measure               | Filter                    |
| ------- | --------------------- | ------------------------- |
| Has abc | Count of observations | Metadata key `abc` exists |
| Has bbc | Count of observations | Metadata key `bbc` exists |

Choose a bar chart and leave the breakdown empty. An observation containing both keys contributes to both bars. An empty value still counts as a present key.

The example dashboard contains 300,000 observations. The bars show 180,000 and 150,000 matches, including 60,000 observations that belong to both groups.

![Keep the preview visible while editing queries and chart settings](/images/changelog/2026-11-17-dashboard-studio-editor.png)

Open a widget in a dedicated editor. The result stays above the query controls, with chart type, title, formatting, and displayed series together on the right. Resize the preview or scroll the queries independently. Each query combines a source, metrics, filters, and optional grouping; advanced settings stay out of the way until needed.

A visible warning marks changes that have not been run, while the chart retains the last result. Use **Run preview**, then **Apply changes** and **Save dashboard**. Presentation settings update the existing result immediately; changes that need different data wait for the next run. The editor shows inherited dashboard filters alongside the query configuration. Invalid formulas show guidance next to the expression. Apply becomes available after a successful preview, including a valid result with no matching rows.

## Make every starting point editable

The familiar Home cards have configurable replacements. Start with cost and tokens by model, user consumption, traffic, latency percentiles, or scores. Their configuration uses the same editor as a chart you create from scratch.

Choose **Add widget → From a template** to start a configurable chart. Choose **Legacy widgets** to compare an existing card with its replacement. Keep both versions, or replace the old card and use **Undo** while editing to restore it. Score analytics expands into ordinary distribution and trend charts.

![The existing traces card beside its editable replacement](/images/changelog/2026-11-17-dashboard-studio-migration.png)

The comparison keeps important meanings visible: root-observation latency differs from reconstructed trace duration, and a count of observations differs from a distinct count of traces. Score queries explicitly select all targets, traces, observations, sessions, or experiments.

## Put the right numbers together

Use several measures in one chart or table. Give a model table separate cost and token columns, and select the cost summary for its headline. Full-period summaries are queried independently of the visible top rows. Percentiles are calculated from the underlying population, rather than averaged across groups.

For a rate, name query A **Errors** and query B **All observations**, then use `a.count / b.count` with **Percent (0–1)** formatting. Choose **Hide from chart** on the inputs to display only the formula. **Data** retains exact input values, raw units, and formula definitions, with local controls to inspect a reference or full-period summaries. Inspecting these results does not rerun the queries. Missing count buckets use zero; missing non-count inputs or a zero denominator produce a gap.

Choose a percentile such as p10 or p99.9. Define exact histogram boundaries, including underflow, overflow, and missing values. Active-day counts use UTC calendar days.

Compatible measures share a chart axis. Measures with different units use a table with individually formatted columns. Choose **Default view** to open a widget on one query, or **Displayed series** to save which model/metric series appear. Legend clicks remain temporary exploration. Series retain their colors after reloading or hiding another series; small desktop comparisons show every legend label. A query filter changes the measured population. Display selection changes what is drawn, and partial selections suppress ambiguous full-population headlines.

Use **Data** to inspect individual values. **Inspect** shows how many requests the existing API made. The experimental backend can also report duration, rows and bytes read, and its generated query.

## Give the dashboard a story

New dashboards open directly in editing mode. Save your changes, then choose **Done** to return to viewing. Choose **Add widget → Text** to place Markdown headings, explanations, lists, and links between charts. Text grows to fit its content and still supports manual resizing. New widgets fill available columns. Duplicate, copy, paste, remove, and undo dashboard items in place. Expand descriptions to read their full caveats.

Dashboard filters apply across compatible widgets. Each series can add its own conditions. A widget shows a filter-scope notice when a shared filter cannot apply to its source. Legend interactions change which series are visible; configured view selectors switch between questions such as model cost and token usage.

The prototype dashboard pairs all twelve Home-card types with their replacements, then demonstrates the new capabilities with real data. It is also the review surface for the remaining backend decisions: keyed metadata breakdowns, relationships between observations and scores, cross-series alignment, scan sharing, and production limits.

## Read a dashboard as a report

Choose **Read as report** to walk through saved charts and Markdown in order. A top-level Markdown heading starts a section. You can edit a chart from its output, add a finding beneath it, and save that cell directly. The dashboard grid and the report share the same saved content.

![A dashboard report compares recorded spend for three selected workloads.](/images/changelog/2026-11-19-dashboard-report.png)

The sample report compares support, search and coding spend using three existing filtered queries. Its scores section plots a named numeric score alongside its evaluation count. Each point is the mean of score records received during the time bucket. A late batch can change the mean even when the application has stayed the same.

![Average quality by week paired with the number of evaluations that contributed to each point.](/images/changelog/2026-11-19-dashboard-score-report.png)

In **Replacing the Home cards**, choose one of twelve cards to inspect its result beside an editable recipe. The notes identify changes that affect migration, including full-period totals, score definitions and sampled latency percentiles. **Compare editors** lets you try the original form, a multi-query form using existing analytics, and proposed query-builder controls. Proposed relationship queries show their contract and have execution disabled.

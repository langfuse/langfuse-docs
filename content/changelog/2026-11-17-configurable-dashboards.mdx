Build charts directly in your dashboard. Start with a familiar preset, change what it measures, and compare several populations in one widget. Add text to explain what your team should take away.

- Compare observations containing `metadata.abc` with observations containing `metadata.bbc`, as two named bars.
- Plot p50 and p90 together, choose a custom percentile, or calculate the share of observations with errors.
- Combine a quality overview with explicit score targets, distribution charts, and notes explaining how to read them.

## Two metadata keys, two series

Each series has its own source, measures, and filters. A breakdown splits that population by a field; another series lets you ask a different question.

| Series  | Measure               | Filter                    |
| ------- | --------------------- | ------------------------- |
| Has abc | Count of observations | Metadata key `abc` exists |
| Has bbc | Count of observations | Metadata key `bbc` exists |

Choose a bar chart and leave the breakdown empty. An observation containing both keys contributes to both bars. An empty value still counts as a present key.

The example dashboard contains 300,000 observations. The bars show 180,000 and 150,000 matches, including 60,000 observations that belong to both groups.

![Edit independently filtered series beside a real chart preview](/images/changelog/2026-11-17-dashboard-studio-editor.png)

Use **Run preview** while editing, then **Apply widget** and **Save dashboard**. Reopen a saved widget to change its source, measures, conditions, breakdown, sorting, or visualization.

## Make every starting point editable

The familiar Home cards have configurable replacements. Start with cost and tokens by model, user consumption, traffic, latency percentiles, or scores. Their configuration uses the same editor as a chart you create from scratch.

Choose **Start from a familiar card** to compare an existing card with its proposed replacement. Keep both versions, or replace the old card and use **Undo** while editing to restore it. Score analytics expands into ordinary distribution and trend charts.

![The existing root-latency card beside its editable replacement](/images/changelog/2026-11-17-dashboard-studio-migration.png)

The comparison keeps important meanings visible: root-observation latency differs from reconstructed trace duration, and a count of observations differs from a distinct count of traces. Score queries explicitly select all targets, traces, observations, sessions, or experiments.

## Put the right numbers together

Use several measures in one chart or table. Give a model table separate cost and token columns, and select the cost summary for its headline. Full-period summaries are queried independently of the visible top rows. Percentiles are calculated from the underlying population, rather than averaged across groups.

For a rate, add **Errors** and **All observations**, then use `Errors / All observations` with **Percent (0–1)** formatting. Keep the input series hidden while displaying the formula. Missing input or a zero denominator produces a gap.

Choose a percentile such as p10 or p99.9. Define exact histogram boundaries, including underflow, overflow, and missing values. Active-day counts use UTC calendar days.

Compatible measures share a chart axis. Measures with different units use a table with individually formatted columns. Switch between **Chart**, **Data**, and **Inspect**; Inspect shows the actual query count, duration, rows and bytes read, and generated queries.

## Give the dashboard a story

Add Markdown headings, explanations, lists, and links between charts. Text moves and resizes alongside widgets. Duplicate, copy, paste, remove, and undo dashboard items in place.

Dashboard filters apply across compatible widgets. Each series can add its own conditions. A widget shows a filter-scope notice when a shared filter cannot apply to its source. Legend interactions change which series are visible; configured view selectors switch between questions such as model cost and token usage.

The prototype dashboard pairs all twelve Home-card types with their replacements, then demonstrates the new capabilities with real data. It is also the review surface for the remaining backend decisions: keyed metadata breakdowns, relationships between observations and scores, cross-series alignment, scan sharing, and production limits.

You can now manage [decision-model evaluators](/docs/evaluation/evaluation-methods/decision-models) through the stable `/api/public/v2/evaluators` endpoints, next to LLM-as-a-Judge and code evaluators. Create them with `type: "decision_model"`, keep them in version control, and attach them to evaluation rules from your deployment pipeline.

A decision-model evaluator definition has three parts:

- **`questions`**: typed `choice`, `score`, or `boolean` questions. Each question lists its allowed answers in `criteria`: options for `choice`, levels from lowest to highest for `score`, and optional `true` and `false` descriptions for `boolean`.
- **`modelConfig`**: the connection `provider` and decision `model`. It is required for decision-model evaluators.
- **`variableMapping`**: which observation data the model receives, mapped to named state keys that the questions refer to.

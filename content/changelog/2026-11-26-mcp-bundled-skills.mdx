MCP is quickly becoming the default way to distribute agent skills, with major agent harnesses and frameworks already supporting or adopting the [MCP Skills extension](https://modelcontextprotocol.io/extensions/skills/overview) — for example [Claude](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more) and others on the [supported clients list](https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/implementations.md#hosts-including-agent-harnesses-ides-and-web-applications). Connect your client to the [Langfuse MCP server](/docs/api-and-data-platform/features/mcp-server) once, and it automatically discovers the official playbooks from [`langfuse/skills`](https://github.com/langfuse/skills) alongside your project tools, with no separate skill installation required.

## Out of the box, always in sync

Serving skills through the MCP server removes the usual setup and maintenance friction for individuals and teams alike:

- **One setup for tools and guidance.** Connecting the MCP server gives your agent both live access to your Langfuse project and the instructions to use it well — no `npx skills add`, cloned repositories, or symlinks to manage.
- **Version-matched automatically.** Langfuse Cloud always serves the latest skills from `langfuse/skills`, while self-hosted deployments serve the skills matching their installed Langfuse version so playbooks stay aligned with your server.
- **Lean context by default.** Skills load progressively via the MCP Skills extension (`io.modelcontextprotocol/skills`), keeping your agent's context window clean until you work on a Langfuse task.

## Set up

Connect your MCP client to your Langfuse host's `/api/public/mcp` endpoint using a project-scoped API key. For regional Cloud endpoints and other MCP clients, see [MCP server setup](/docs/api-and-data-platform/features/mcp-server#set-up).

<Steps>

### Get authentication header

1. Navigate to your project settings and create or copy a **project-scoped API key**:
   - Public Key: `pk-lf-...`
   - Secret Key: `sk-lf-...`
2. Encode the credentials to base64 format:
   ```bash filename="your-base64-token"
   echo -n "pk-lf-your-public-key:sk-lf-your-secret-key" | base64
   ```

### Client setup

<Tabs items={["Claude Code", "Codex", "Other"]}>

<Tab>

1. Register the Langfuse MCP server with a single command, replacing `{your-langfuse-host}` with your Langfuse host and `{your-base64-token}` with your encoded credentials:

   ```bash filename="terminal" /{your-base64-token}/
   claude mcp add --transport http langfuse https://{your-langfuse-host}/api/public/mcp \
       --header "Authorization: Basic {your-base64-token}"
   ```

2. Verify the connection by asking Claude Code to `list all prompts in the project`. Claude Code should use the `listPrompts` tool to return the list of prompts.

</Tab>

<Tab>

1. Add the Langfuse MCP server to `~/.codex/config.toml`, replacing `{your-langfuse-host}` with your Langfuse host and `{your-base64-token}` with your encoded credentials:

   ```toml filename="~/.codex/config.toml" /{your-base64-token}/
   [mcp_servers.langfuse]
   url = "https://{your-langfuse-host}/api/public/mcp"
   http_headers = { "Authorization" = "Basic {your-base64-token}" }
   ```

2. Restart Codex and run `codex mcp list` to confirm the server is registered.
3. Verify the connection by asking Codex to `list all prompts in the project`. Codex should use the `listPrompts` tool to return the list of prompts.

</Tab>

<Tab>

For other MCP clients (such as Cursor, Pi Agent, or any client supporting `streamableHttp`), see the [MCP server setup guide](/docs/api-and-data-platform/features/mcp-server#set-up).

</Tab>

</Tabs>

</Steps>

Using an MCP client that doesn't support MCP skills yet? You can still [install the Langfuse Agent Skill from GitHub](/docs/api-and-data-platform/features/agent-skill#install) or via the Cursor plugin, and use it alongside the MCP server or the [Langfuse CLI](/docs/api-and-data-platform/features/cli).

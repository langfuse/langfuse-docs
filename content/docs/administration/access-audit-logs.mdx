# Read-access audit logs

<AvailabilityBanner
  availability={{

[Audit logs](/docs/administration/audit-logs) record changes. Read-access audit logs also record reads. When a user or API key reads traces, observations, scores, sessions or experiments through one of the [covered views, API routes and MCP tools](#coverage), Langfuse records an access event. Use these events to answer questions such as "who opened this trace?" or "which traces did this user see in a search?".

Access events appear in the audit log viewer next to change events.

## Turn on read-access logging [#activate]

Read-access logging is off by default.

### Organization setting

1. Go to **Organization settings** → **Audit Logs**.
2. Turn on **Access Logging**.

Langfuse records reads in every project of the organization from then on. Reads from before you turned it on are not recorded. Turning it on or off is recorded as a change event.

To change the setting, you need permission to update the organization (the organization `OWNER` or `ADMIN` role). The setting is available on Langfuse Cloud Enterprise plans and on self-hosted instances with an Enterprise or Government license key.

<Callout type="info">
  On Langfuse Cloud HIPAA (`hipaa.cloud.langfuse.com`), read-access logging is always on for every organization, and the setting is not shown.
</Callout>

### Self-hosted: instance setting [#self-hosted]

Instance administrators can set read-access logging for all organizations with `LANGFUSE_AUDIT_LOG_ACCESS_EVENTS` on the web container:

| Value           | Behavior                                                                      |
| --------------- | ----------------------------------------------------------------------------- |
| `org` (default) | Each organization decides with the **Access Logging** setting.                |
| `enforced`      | Reads are recorded in every organization. The organization setting is hidden. |
| `disabled`      | Reads are never recorded. The organization setting is hidden.                 |

Requirements:

- An Enterprise or Government [license key](/self-hosting/license-key) (`LANGFUSE_EE_LICENSE_KEY`) on the web and worker containers. Without one, nothing is recorded, even with `enforced`.
- Langfuse `v4.79.0` or later to record access events, and `v4.82.0` or later to see them in the audit log viewer and export.
- A running worker. It moves access events into the ClickHouse `audit_logs` table.
- The v4 write mode `events_only`, which is the v4 default. Coverage follows the v4 views and APIs. In the `legacy` and `dual` write modes, the v3 trace and session tables and the v3 public API list routes return data without recording it. See [cutting over to the v4 defaults](/self-hosting/upgrade/upgrade-guides/upgrade-v3-to-v4#cutover).

If Langfuse runs behind a load balancer or reverse proxy, also set `LANGFUSE_TRUSTED_PROXY_COUNT` to the number of proxies in front of it. Otherwise access events from the Langfuse UI carry no client IP address, and events from the public API and MCP carry the address of your proxy.

| Variable                               | Default | Container | Description                                                                                                                                      |
| -------------------------------------- | ------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `LANGFUSE_AUDIT_LOG_ACCESS_EVENTS`     | `org`   | web       | `org`, `enforced` or `disabled`, see above.                                                                                                      |
| `LANGFUSE_TRUSTED_PROXY_COUNT`         | `0`     | web       | Number of proxies in front of Langfuse that append to `X-Forwarded-For`. The client IP is the N-th entry from the right. `0` ignores the header. |
| `LANGFUSE_AUDIT_LOG_STAGING_ENABLED`   | `true`  | web       | Kill switch. `false` stops recording access events, and reads then succeed without being recorded.                                               |
| `LANGFUSE_AUDIT_LOG_RELAY_ENABLED`     | `true`  | worker    | Moves recorded events from Postgres into ClickHouse. While it is `false`, events wait in Postgres and do not appear in the audit log viewer.     |
| `LANGFUSE_AUDIT_LOG_RELAY_INTERVAL_MS` | `10000` | worker    | How often, in milliseconds, the worker moves events into ClickHouse.                                                                             |

## How it works [#how-it-works]

- **Recorded before data is returned.** Langfuse writes the access event before it returns any data. If that write fails, the read fails with an error, so no data is returned without a record. A batch export whose event cannot be written is marked as failed and does not run.
- **One event per request.** Opening a trace sends several requests, so one trace view produces several events.
- **Lists record what was shown.** A list or search records its request parameters, the number of rows returned and the id of every returned row, up to 10,000 ids per event.
- **Refused reads.** A read in the Langfuse UI that is refused for missing permissions is recorded with the outcome `denied`. Public API and MCP calls are recorded only when they succeed.
- **Retention.** Audit log retention is not configurable yet, and project [data retention](/docs/administration/data-retention) does not apply to audit logs. If your compliance program requires you to keep access records for a set period, export them regularly and store the exports yourself.

## What is recorded [#coverage]

| Surface     | Recorded reads                                                                                                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Langfuse UI | Trace and observation detail views, including input and output; the tracing, sessions, scores and experiments tables; session, score and experiment detail views; trace and observation downloads; creating a batch export |
| Public API  | `GET /api/public/v2/observations`, `GET /api/public/v3/scores`, `GET /api/public/experiments`, `GET /api/public/experiment-items`, and `GET /api/public/traces/{traceId}` where that v3 route is still served              |
| MCP server  | `getObservation`, `getScore`, `listObservations`, `listScores`, `listExperiments`, `listExperimentItems`                                                                                                                   |

`GET /api/public/traces/{traceId}` is a v3 route. On self-hosted instances in the `events_only` write mode it returns `404` and is not recorded.

Not recorded:

- Aggregates: counts, filter options, metrics and dashboards, including the metrics API and the MCP tool `queryMetrics`.
- Prompts, datasets, comments and media.
- Scheduled blob storage exports.
- Other public API routes, including the v3 list routes.
- Anonymous viewers of [public traces](/docs/observability/features/url).

Downloading the file of a finished batch export is recorded as a change event in the regular audit log.

## View and export access events [#view]

Access events appear in the project's audit log viewer (**Project settings** → **Audit Logs**), together with change events. You need the `auditLogs:read` permission, which the project `OWNER` and `ADMIN` roles have.

- The **Event** column tells access events from change events.
- The **Outcome** column shows whether the read succeeded or was denied.
- Filtering by event, actor, resource or time is not available yet.

The export from the audit log viewer contains all events of the project, including for each access event its route, request parameters, result count and the ids of the returned rows.

The client IP address, user agent and request id are recorded but not shown in the viewer or the export yet. On self-hosted instances, [query ClickHouse](#query) to read them.

## Event fields [#fields]

| Field                                 | Content                                                                                                         |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `timestamp`                           | When the read happened.                                                                                         |
| `org_id`, `project_id`                | The organization and project that were read.                                                                    |
| `event_kind`                          | `access` for reads, `change` for changes.                                                                       |
| `actor_type`, `user_id`, `api_key_id` | Who read the data: `USER`, `API_KEY` or `SYSTEM`.                                                               |
| `actor_name`, `actor_email`           | The user's name and email at the time of the read. They remain after the user leaves the organization.          |
| `user_org_role`, `user_project_role`  | The user's roles at the time of the read.                                                                       |
| `surface`                             | `trpc` (Langfuse UI), `public-api`, `mcp`, or `internal-api` (trace and observation downloads).                 |
| `route`                               | The UI procedure, API route or MCP tool, for example `GET /api/public/v2/observations`.                         |
| `resource_type`, `action`             | What was read and how, for example `trace` and `read`, `observation` and `list`, or `batchExport` and `export`. |
| `resource_refs`                       | Typed ids of the returned rows: `trace:<id>`, `observation:<id>`, `score:<id>` and `session:<id>`.              |
| `params`                              | The request's filters, search and pagination as JSON, cut at 2 KB. A cut value ends in `...[truncated]`.        |
| `result_count`                        | The number of rows returned.                                                                                    |
| `outcome`, `outcome_reason`           | `success`, or `denied` with `UNAUTHORIZED` or `FORBIDDEN`.                                                      |
| `ip`, `user_agent`                    | The client's IP address and user agent.                                                                         |
| `request_id`                          | The OpenTelemetry trace id of the request, if it was sampled.                                                   |

## Self-hosted: query ClickHouse [#query]

Self-hosted instances can query the `audit_logs` table in their ClickHouse database directly, for example with `clickhouse client`. Use `FINAL`: a retried move can store an event twice, and `FINAL` collapses the copies.

Who accessed a trace:

```sql
SELECT timestamp, actor_type, actor_email, api_key_id, ip, surface, route, action, outcome
FROM audit_logs FINAL
WHERE org_id = '<org-id>'
  AND project_id = '<project-id>'
  AND event_kind = 'access'
  AND has(resource_refs, 'trace:<trace-id>')
ORDER BY timestamp DESC;
```

What a user read during a period:

```sql
SELECT timestamp, route, resource_type, action, result_count, params
FROM audit_logs FINAL
WHERE org_id = '<org-id>'
  AND event_kind = 'access'
  AND user_id = '<user-id>'
  AND timestamp >= '2026-11-01 00:00:00'
  AND timestamp < '2026-11-08 00:00:00'
ORDER BY timestamp;
```

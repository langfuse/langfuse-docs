# Model management

<AiGatewayBetaCallout />

The gateway uses your organization's own provider keys (bring your own key). It offers the models those provider credentials can access, minus the models an admin turned off. This page explains where the model list comes from, how admins choose models, and which model ID to send.

## Available models [#available-models]

Go to **Organization settings → AI Gateway → Models** to see every model gateway keys can call, with its provider, provider credential, and API formats. Everyone with gateway access can open this page, including Viewers and the AI Gateway role.

The list comes from each provider credential:

- The gateway asks the provider's own `/models` endpoint which models the credential can access. New provider models appear without a Langfuse update.
- OpenAI credentials serve the OpenAI Responses and Chat Completions formats. Anthropic credentials serve the Anthropic Messages format. See [API formats](/docs/ai-gateway/features/api-formats).
- Clients get the same list from `GET /openai/v1/models` and `GET /anthropic/v1/models`, filtered by the format of the route.

<Callout type="warning">
  If a provider rejects a credential during model discovery, for example
  because the key was rotated, the credential is marked as failing and the
  gateway stops routing to it. Update the key or select **Retry** in
  **Organization settings → AI Gateway → Setup** to restore it.
</Callout>

## Manage models [#manage-models]

Gateway managers (Owners and Admins) choose models per provider credential:

1. Go to **Organization settings → AI Gateway → Setup** and open a provider credential.
2. Turn models on or off with the **Enabled** switch, or select several models and change them together. **Enable all** and **Disable all** change every model at once.
3. Select **Refresh provider models** to fetch the provider's current list.

A credential with every model enabled also allows models that the provider publishes later. As soon as you turn one model off, the credential keeps an explicit list: models the provider adds later stay off until you enable them. Select **Enable all** to go back to allowing every model. See [Why can't I call a new model?](#new-models).

## Model IDs [#model-ids]

Use the **prefixed** form `<credential>:<model>`, for example `openai-prod:<model>`. This is the form the **Models** page and `/models` return. It always routes to the named credential, works for every model, and keeps working when your organization adds a second credential for the same provider. The gateway removes the prefix before it calls the provider. Renaming a provider credential changes its prefix, so update clients that use the old IDs.

**Bare** provider IDs without a prefix, for example `claude-…`, exist for compatibility with coding agents that don't discover models from `/models` and send the provider's own model names, such as [Codex](/docs/ai-gateway/coding-agents/codex) or [Claude Code](/docs/ai-gateway/coding-agents/claude-code) by default. They only work for models whose names start with `gpt-`, `codex-`, or `ft:` (sent to an OpenAI credential) or `claude-` (sent to an Anthropic credential). When several credentials of that provider exist, the oldest one that allows the model serves the request.

The gateway doesn't fall back to another credential or model when a provider call fails. For model errors such as `403 model_not_allowed` or `400 Invalid gateway model`, see [Troubleshooting](/docs/ai-gateway/troubleshooting-and-faq#troubleshooting).

## Troubleshooting and FAQ [#troubleshooting-and-faq]

<FaqDetails>

<Details id="new-models">
<Summary>Why can't I call a new model?</Summary>

A model the provider just released is available right away only on credentials that have every model enabled. If an admin turned off any model on a credential, the credential keeps an explicit list, and new models stay off until an admin enables them under **Organization settings → AI Gateway → Setup**. Select **Refresh provider models** there if the model doesn't appear in the list yet.

</Details>

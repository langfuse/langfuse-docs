# Set up the gateway

<AiGatewayBetaCallout />

This page walks an organization admin through preparing the gateway for a team. Complete the steps in order. Each step links to the page that covers its topic in full. If you only want to call the gateway, go to [Send your first request](/docs/ai-gateway/get-started/first-request).

## Before you begin [#prerequisites]

- **Langfuse Cloud:** the gateway is available to every organization, with no extra setup.
- **Self-hosted Langfuse:** the gateway is a separate service that runs next to Langfuse. Until it is deployed, the AI Gateway settings show a notice instead of the setup page. See [Self-hosting the AI Gateway](/self-hosting/configuration/ai-gateway).
- **Role:** the setup steps need the Owner or Admin [organization role](/docs/administration/rbac).

All gateway settings are under **Organization settings → AI Gateway**.

## Setup steps [#setup-steps]

<Steps>

### Configure the gateway [#configure-the-gateway]

Go to **Organization settings → AI Gateway → Setup** and choose:

- the **ingestion project**, where the gateway records generations
- the [ingestion mode](/docs/ai-gateway/features/tracing#ingestion-modes): `FULL` (input and output) or `USAGE` (usage and cost only, the default). Self-hosted deployments also offer `NONE` (route without recording).

Both are set per organization, not per key. The other AI Gateway pages stay disabled until an ingestion project is set (not needed with `NONE` on self-hosted Langfuse).

### Add provider credentials [#add-provider-connections]

On the same page, select **Add credential** and add an OpenAI or Anthropic API key. The key is validated when you save it. The credential's **name** becomes the prefix of its [model IDs](/docs/ai-gateway/features/models#model-ids), so renaming a credential changes them.

<Callout type="warning">
  **HIPAA region:** requests are forwarded to the provider you configure, using
  your credentials and on your instruction. Before you send protected health
  information (PHI) through the gateway, make sure you have a [BAA with
  Langfuse](/security/hipaa) and a BAA with that provider.
</Callout>

Provider credentials are separate from project [LLM connections](/docs/administration/llm-connection), which power the Playground and LLM-as-a-Judge.

### Choose models [#choose-models]

By default, a credential allows every model the provider offers, including models the provider publishes later. To restrict a credential to selected models, turn models off on its models page. See [Model management](/docs/ai-gateway/features/models#manage-models).

### Give your team access [#give-your-team-access]

Use **Notify your team** in the setup guide to email teammates. People who are not in the organization yet are invited with the AI Gateway role: they can call the gateway and manage their own keys, but can't see any projects. This role suits people who only need to call models, for example developers who use the gateway for their coding agent.

You can change anyone's role later in the organization's members settings, for example to let them see their traces in the ingestion project. See [roles and permissions](/docs/administration/rbac) for what each role can do.

<Callout type="warning">
  To see traces, people need access to the ingestion project. Everyone with
  access to that project sees every gateway trace in it, not only their own.
</Callout>

### Create a gateway API key [#create-a-gateway-api-key]

Share [Send your first request](/docs/ai-gateway/get-started/first-request) with your developers: it shows how to create a gateway key and call a model. Gateway keys can only call the gateway and have no other permissions in Langfuse, see [API keys](/docs/ai-gateway/features/api-keys).

</Steps>

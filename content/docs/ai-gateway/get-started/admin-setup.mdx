# Set up the gateway

<AiGatewayBetaCallout />

This page walks an organization admin through preparing the gateway for a team. Complete the steps in order. Each step links to the page that covers its topic in full. If you only want to call the gateway, go to [Send your first request](/docs/ai-gateway/get-started/first-request).

## Before you begin [#prerequisites]

- **Langfuse Cloud:** the gateway is available to every organization, with no extra setup.
- **Self-hosted Langfuse:** the gateway is a separate service that runs next to Langfuse. Until it is deployed, the AI Gateway settings show a notice instead of the setup page. See [Self-hosting the AI Gateway](/self-hosting/configuration/ai-gateway).
- **Role:** the setup steps need the `OWNER` or `ADMIN` organization role.

All gateway settings are under **Organization settings → AI Gateway**.

## Setup steps [#setup-steps]

<Steps>

### Configure the gateway [#configure-the-gateway]

Go to **Organization settings → AI Gateway → Setup** and choose:

- the **ingestion project**, where the gateway records generations
- the [capture mode](/docs/ai-gateway/features/tracing#capture-modes): `FULL` (input and output) or `USAGE` (usage and cost only, the default). Self-hosted deployments also offer `NONE` (route without recording).

Both are set per organization, not per key. The other AI Gateway pages stay disabled until an ingestion project is set (not needed with `NONE` on self-hosted Langfuse).

### Add provider credentials [#add-provider-connections]

On the same page, select **Add credential** and add an OpenAI or Anthropic API key:

- an `OPENAI` credential serves the OpenAI routes (Codex, OpenAI SDKs, and the OpenAI routes of OpenCode, pi, and GitHub Copilot)
- an `ANTHROPIC` credential serves the Anthropic route (Claude Code, Claude Desktop, and the Anthropic routes of OpenCode, pi, and GitHub Copilot)

Each credential needs a **name** of letters, numbers, `-` and `_`, starting with a letter or number, at most 64 characters. `ft` is reserved. The name becomes the prefix of the credential's [model IDs](/docs/ai-gateway/features/models#model-ids), so renaming a credential changes them. The key is validated when you save it, and the gateway always calls the vendor's official base URL.

<Callout type="warning">
  **HIPAA region:** requests are forwarded to the provider you configure, using
  your credentials and on your instruction. Before you send protected health
  information (PHI) through the gateway, make sure you have a [BAA with
  Langfuse](/security/hipaa) and a BAA with that provider.
</Callout>

Provider credentials are separate from project [LLM connections](/docs/administration/llm-connection), which power the Playground and LLM-as-a-Judge.

### Choose models [#choose-models]

By default, a credential allows every model the provider offers, including models the provider publishes later. To restrict a credential to selected models, turn models off on its models page. See [Models](/docs/ai-gateway/features/models#manage-models).

### Give your team access [#give-your-team-access]

Who can do what depends on the organization role:

| Role                  | Gateway access                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------ |
| `OWNER`               | Everything below, plus setup, provider credentials, models, analytics, and service account keys        |
| `ADMIN`               | Same as `OWNER`                                                                                        |
| `MEMBER`              | Sees the enabled models, creates and revokes their own gateway keys                                    |
| AI Gateway            | Same gateway access as `MEMBER`, with no access to projects or other organization settings             |
| `VIEWER`              | Sees the enabled models, cannot create gateway keys or call the gateway                                |
| `NONE` (organization) | No gateway access                                                                                      |

The **AI Gateway** role is for people who only need to call models, for example developers who use the gateway for their coding agent. Assign it in the organization's members settings. See [roles and permissions](/docs/administration/rbac) for all roles and project access.

Use **Notify your team** in the setup guide to email teammates. People who are not in the organization yet are invited with the **AI Gateway** role: they can call the gateway and manage their own keys, but can't open projects. To let them see their traces, give them a role on the ingestion project, or change their organization role.

<Callout type="warning">
  To see traces, people need access to the ingestion project. Everyone with
  access to that project sees every gateway trace in it, not only their own.
</Callout>

### Create a gateway API key [#create-a-gateway-api-key]

Developers create their own keys under **Organization settings → AI Gateway → Gateway keys**. A key created there is tied to its creator and stops working when they lose gateway access. For a shared service, CI, or an agent that should keep working when people leave, issue a **service account** key instead. See [API keys](/docs/ai-gateway/features/api-keys) for both key types.

</Steps>

## Send a test request [#test]

Follow [Send your first request](/docs/ai-gateway/get-started/first-request) to check the setup end to end. Share the same page with your developers as their starting guide.

# Send your first request

<AiGatewayBetaCallout />

This page is for developers who want to call models through the gateway. You create a gateway API key and send a request. If the gateway is not set up for your organization yet, ask an admin to follow [Set up the gateway](/docs/ai-gateway/get-started/admin-setup) first.

## Before you begin [#prerequisites]

- Your organization has set up the gateway and added at least one provider credential. **Organization settings → AI Gateway → Models** lists the models you can call. If it says "No active providers", ask your admin.
- You have the AI Gateway, Member, Admin, or Owner organization role. Viewers can't create gateway keys. See [roles and permissions](/docs/administration/rbac).
- To see traces, you need access to the organization's ingestion project.

<Steps>

### Create a gateway API key [#create-a-key]

Go to **Organization settings → AI Gateway → Gateway keys** and select **Issue API key**. Give the key a name and optionally set an expiry. Copy the secret key: it's shown only once.

Your key records you as the user of every trace, and stops working when you leave the organization or lose gateway access. For CI or a shared service, ask an admin for a service account key. See [API keys](/docs/ai-gateway/features/api-keys).

<Callout type="warning">
  Never paste a gateway key into a repository, a ticket, or a shared config
  file. Anyone with the key can call models on your organization's provider
  account.
</Callout>

### Export the key [#export-the-key]

Export the gateway host and key in your shell. The examples on this page use these variables. To configure a coding agent instead, follow the [coding agent guides](/docs/ai-gateway/coding-agents).

```sh
export LANGFUSE_GATEWAY_HOST="https://gateway.cloud.langfuse.com"   # EU; see the table below for other regions
export LANGFUSE_GATEWAY_KEY="<your-gateway-key>"
```

#### Gateway hosts [#gateway-hosts]

Use the gateway host of the region your organization is in. A gateway key only works on its own region's host.

| Region | Langfuse Cloud             | Gateway host                               |
| ------ | -------------------------- | ------------------------------------------ |
| EU     | `cloud.langfuse.com`       | `https://gateway.cloud.langfuse.com`       |
| US     | `us.cloud.langfuse.com`    | `https://gateway.us.cloud.langfuse.com`    |
| JP     | `jp.cloud.langfuse.com`    | `https://gateway.jp.cloud.langfuse.com`    |
| HIPAA  | `hipaa.cloud.langfuse.com` | `https://gateway.hipaa.cloud.langfuse.com` |

On self-hosted Langfuse, use the gateway URL your deployment configured (`LANGFUSE_AI_GATEWAY_PUBLIC_URL`, see [Self-hosting the AI Gateway](/self-hosting/configuration/ai-gateway)).

The gateway is path-routed: OpenAI under `/openai/v1`, Anthropic under `/anthropic/v1`. All snippets in these docs use the EU host.

### Pick a model [#list-models]

Go to **Organization settings → AI Gateway → Models** to see the models you can call, and copy a model ID. Each ID has the form `<credential>:<model>`, for example `openai-prod:<model>`. See [model IDs](/docs/ai-gateway/features/models#model-ids) for which form to send.

<Callout type="info">
  To list the models from the command line instead, call the gateway's models
  endpoint. A model list also confirms that your key works.

```sh
curl -s "$LANGFUSE_GATEWAY_HOST/openai/v1/models" \
  -H "Authorization: Bearer $LANGFUSE_GATEWAY_KEY" | head -c 300

curl -s "$LANGFUSE_GATEWAY_HOST/anthropic/v1/models?limit=1000" \
  -H "x-api-key: $LANGFUSE_GATEWAY_KEY" \
  -H "anthropic-version: 2023-06-01" | head -c 300
```

</Callout>

### Send a request [#send-a-request]

Call a model with the OpenAI Chat Completions API:

```sh
curl -si "$LANGFUSE_GATEWAY_HOST/openai/v1/chat/completions" \
  -H "Authorization: Bearer $LANGFUSE_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -H "langfuse-tags: first-request" \
  -d '{"model":"<model-id>","messages":[{"role":"user","content":"Say hello"}]}'
```

Replace `<model-id>` with the model ID you picked. The response is OpenAI's own response. Its headers include `langfuse-trace-id`, the ID of the trace the gateway recorded. To use an SDK instead, see the [OpenAI SDK](/docs/ai-gateway/sdks-and-apis/openai-sdk), [Anthropic SDK](/docs/ai-gateway/sdks-and-apis/anthropic-sdk), or [Vercel AI SDK](/docs/ai-gateway/sdks-and-apis/vercel-ai-sdk) guide. For all endpoints, see the [REST API reference](/docs/ai-gateway/sdks-and-apis/rest-api).

### View the trace (optional) [#view-the-trace]

This step needs access to the organization's ingestion project. Open the ingestion project in Langfuse and go to **Tracing**. The call appears as a trace with a generation named `openai.chat-completions`, with its input, output, token usage, and cost. Filter by the `first-request` tag, or by your user: your key records your email as the trace user.

What's recorded depends on the organization's [ingestion mode](/docs/ai-gateway/features/tracing#ingestion-modes).

</Steps>

## Connect a coding agent [#connect-a-coding-agent]

To route your coding agent through the gateway, follow its guide: [Claude Code](/docs/ai-gateway/coding-agents/claude-code), [Codex](/docs/ai-gateway/coding-agents/codex), [OpenCode](/docs/ai-gateway/coding-agents/opencode), [pi](/docs/ai-gateway/coding-agents/pi), or [GitHub Copilot](/docs/ai-gateway/coding-agents/github-copilot). The guides use the EU host. Replace it with your region's [gateway host](#gateway-hosts).

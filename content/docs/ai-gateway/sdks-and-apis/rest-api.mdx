# REST API reference

<AiGatewayBetaCallout />

The gateway serves an OpenAI route and an Anthropic route. Each route lists the models your key can call and relays the provider's inference APIs. To call the gateway from code, you can also use the [OpenAI SDK](/docs/ai-gateway/sdks-and-apis/openai-sdk), the [Anthropic SDK](/docs/ai-gateway/sdks-and-apis/anthropic-sdk), or the [Vercel AI SDK](/docs/ai-gateway/sdks-and-apis/vercel-ai-sdk).

## Base URLs [#base-urls]

| Route     | Base URL                                          |
| --------- | ------------------------------------------------- |
| OpenAI    | `https://gateway.cloud.langfuse.com/openai/v1`    |
| Anthropic | `https://gateway.cloud.langfuse.com/anthropic/v1` |

These are the EU URLs. For other regions and self-hosted Langfuse, replace the host with your [gateway host](/docs/ai-gateway/get-started/first-request#gateway-hosts). The examples on this page use the `LANGFUSE_GATEWAY_HOST` and `LANGFUSE_GATEWAY_KEY` variables from [Send your first request](/docs/ai-gateway/get-started/first-request#export-the-key).

## Authentication [#authentication]

Every endpoint, including the models endpoints, requires a [gateway API key](/docs/ai-gateway/features/api-keys). How you send it depends on the route.

<Tabs items={["OpenAI", "Anthropic"]}>
<Tab>

Send the key as a Bearer token.

```http
Authorization: Bearer <gateway key>
```

</Tab>
<Tab>

Send the key in the `x-api-key` header, like an Anthropic API key, or as a Bearer token. If you send both headers, they must have the same value.

```http
x-api-key: <gateway key>
```

</Tab>
</Tabs>

## Endpoints [#routes]

| Endpoint                                                | Description                                           |
| ------------------------------------------------------- | ----------------------------------------------------- |
| [`GET /openai/v1/models`](#list-models)                 | List the models of your OpenAI credentials            |
| [`GET /anthropic/v1/models`](#list-models)              | List the models of your Anthropic credentials         |
| [`POST /openai/v1/responses`](#responses)               | Create a model response with the OpenAI Responses API |
| [`POST /openai/v1/responses/compact`](#responses)       | Compact a Responses API conversation                  |
| [`POST /openai/v1/chat/completions`](#chat-completions) | Create a chat completion                              |
| [`POST /anthropic/v1/messages`](#messages)              | Create a message with the Anthropic Messages API      |
| [`POST /anthropic/v1/messages/count_tokens`](#messages) | Count the tokens of a message                         |

The Responses, Chat Completions, and Messages endpoints relay the provider's API. The gateway doesn't translate between formats, so the OpenAI endpoints need an OpenAI provider credential and the Anthropic endpoints an Anthropic credential. Replace `<model-id>` in the examples with an ID from [List models](#list-models).

<Callout type="info">
  Other paths return `404`, including websockets, realtime APIs, and decision
  model APIs (OpenAI Decisions, TypeSafe System One). The gateway only accepts
  uncompressed request bodies: a request with a `Content-Encoding` header other
  than `identity` fails with `415`.
</Callout>

## List models [#list-models]

```http
GET /openai/v1/models
GET /anthropic/v1/models
```

Lists the models your key can call, in the provider's own list format. The OpenAI route lists the models of your organization's OpenAI credentials, and the Anthropic route those of its Anthropic credentials. Models an admin turned off are not listed, see [Model management](/docs/ai-gateway/features/models).

Use the returned `id` as the `model` of your inference requests. Both endpoints return every model in one response, so you don't need pagination parameters.

**Example request**

<Tabs items={["OpenAI", "Anthropic"]}>
<Tab>

```sh
curl "$LANGFUSE_GATEWAY_HOST/openai/v1/models" \
  -H "Authorization: Bearer $LANGFUSE_GATEWAY_KEY"
```

</Tab>
<Tab>

```sh
curl "$LANGFUSE_GATEWAY_HOST/anthropic/v1/models" \
  -H "x-api-key: $LANGFUSE_GATEWAY_KEY"
```

</Tab>
</Tabs>

**Response fields**

<Tabs items={["OpenAI", "Anthropic"]}>
<Tab>

| Field             | Type    | Description                                                                                              |
| ----------------- | ------- | -------------------------------------------------------------------------------------------------------- |
| `object`          | string  | Always `"list"`                                                                                          |
| `data[].id`       | string  | Model ID in the form `<credential>:<model>`, see [model IDs](/docs/ai-gateway/features/models#model-ids) |

| --------------------- | ------- | -------------------------------------------------------------------------------------------------------- |

## OpenAI Responses [#responses]

```http
POST /openai/v1/responses
POST /openai/v1/responses/compact
```

Creates a model response with the OpenAI Responses API, or compacts a conversation. Request and response bodies are OpenAI's own, see the [OpenAI Responses API reference](https://developers.openai.com/api/reference/resources/responses/methods/create) and [compact reference](https://developers.openai.com/api/reference/resources/responses/methods/compact).

**Example request**

```sh
curl "$LANGFUSE_GATEWAY_HOST/openai/v1/responses" \
  -H "Authorization: Bearer $LANGFUSE_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model-id>","input":"Say hello"}'
```

## OpenAI Chat Completions [#chat-completions]

```http
POST /openai/v1/chat/completions
```

Creates a chat completion. Request and response bodies are OpenAI's own, see the [OpenAI Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

**Example request**

```sh
curl "$LANGFUSE_GATEWAY_HOST/openai/v1/chat/completions" \
  -H "Authorization: Bearer $LANGFUSE_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model-id>","messages":[{"role":"user","content":"Say hello"}]}'
```

### Streaming usage [#streaming-usage]

OpenAI only reports usage for a streamed Chat Completions request when the request sets `stream_options.include_usage`. So that every streamed call still gets token usage and cost, the gateway adds `"include_usage": true` to the request it sends upstream when a request has `"stream": true` and does not already set it. The recorded request is your original request, without the added option.

<Callout type="warning">
  Your client receives OpenAI's final usage chunk even if it didn't ask for
  usage: an extra event with an **empty `choices` array** and a `usage` object,
  just before `data: [DONE]`. Code that reads `chunk.choices[0]` on every chunk
  needs a guard.
</Callout>

## Anthropic Messages [#messages]

```http
POST /anthropic/v1/messages
POST /anthropic/v1/messages/count_tokens
```

Creates a message with the Anthropic Messages API, or counts the tokens of a message. Request and response bodies are Anthropic's own, see the Claude API references for [Messages](https://platform.claude.com/docs/en/api/messages/create) and [token counting](https://platform.claude.com/docs/en/api/messages/count_tokens).

**Example request**

```sh
curl "$LANGFUSE_GATEWAY_HOST/anthropic/v1/messages" \
  -H "x-api-key: $LANGFUSE_GATEWAY_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model-id>","max_tokens":1024,"messages":[{"role":"user","content":"Say hello"}]}'
```

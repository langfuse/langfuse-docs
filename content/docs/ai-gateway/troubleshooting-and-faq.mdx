## Troubleshooting [#troubleshooting]

| Symptom                                                                              | Meaning                                                                                                                                                                      | Fix                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **401** `Invalid gateway credential`                                                 | The key is missing, unknown, expired, or disabled.                                                                                                                           | Check that `LANGFUSE_GATEWAY_KEY` is exported in the shell that runs the agent, and that the key is still active. For Codex, check `$CODEX_HOME/.env` (default `~/.codex/.env`): it [overrides](/docs/ai-gateway/coding-agents/codex#store-the-key) a value exported in the shell. |
| **401** on an OpenAI route with only `x-api-key` set                                 | The OpenAI routes read the key only from `Authorization: Bearer`.                                                                                                            | Send `Authorization: Bearer <gateway key>`. `x-api-key` works only on the Anthropic route.                                                                                                                                                                                         |
| **401** `Conflicting gateway credentials in the Authorization and x-api-key headers` | Both headers were sent with different values. Typical case: Claude Code with a leftover `ANTHROPIC_API_KEY` next to `ANTHROPIC_AUTH_TOKEN`.                                  | Run `unset ANTHROPIC_API_KEY`, or give both the same value. For pi, don't add a manual `Authorization` header next to `apiKey`.                                                                                                                                                    |
| **401** with a provider-looking key                                                  | The agent sends a stored provider credential instead of the gateway key (for example `opencode auth` or `OPENAI_API_KEY`).                                                   | Remove the stored credential or environment variable.                                                                                                                                                                                                                              |
| **403** `Gateway access forbidden`                                                   | The key belongs to a user who can no longer call the gateway (for example, their role changed to `VIEWER`), or the organization has no usable ingestion project.             | Check the key owner's organization role (see [access](/docs/ai-gateway/get-started/admin-setup#give-your-team-access)), and check that an ingestion project is set in **Organization settings → AI Gateway → Setup**. Role changes can take up to 60 seconds to reach existing keys. |
| **403** `model_not_allowed`                                                          | The model is turned off on the provider credential that serves the request.                                                                                                  | Pick an enabled model from `/models`, or ask an admin to [enable it](/docs/ai-gateway/features/models#manage-models).                                                                                                                                                              |
| **404** `No eligible provider connection`                                            | No enabled provider credential serves this API format, for example a Claude Code call without an `ANTHROPIC` credential, or the model ID's prefix doesn't name a credential. | Add or fix the credential in **Organization settings → AI Gateway → Setup**, or use a model ID from `/models`. See [routing](/docs/ai-gateway/features/models#routing).                                                                                                            |
| **404** with an empty body on every call                                             | Wrong path.                                                                                                                                                                  | Claude Code and pi use `…/anthropic`. OpenCode uses `…/anthropic/v1`. Everything on OpenAI uses `…/openai/v1`. Chat Completions is served at `…/openai/v1/chat/completions`. See your [coding agent guide](/docs/ai-gateway/coding-agents).                                        |
| **404** `not_found_error` / `model_not_found`                                        | The provider doesn't know the model, or your provider account has no access to it. On the Anthropic route, the gateway's own `404` errors also use the type `not_found_error`. | Read the error message: `No eligible provider connection` comes from the gateway (see the row above). Otherwise, check the ID with `/models` (see [list models](/docs/ai-gateway/get-started/first-request#list-models)). A provider `404` is still recorded as `ERROR`.          |
| **400** `Invalid gateway model`                                                      | The model ID has no credential prefix and doesn't start with `gpt-`, `codex-`, `claude-`, or `ft:`.                                                                          | Use the `<credential>:<model>` ID from `/models`. See [model IDs](/docs/ai-gateway/features/models#model-ids).                                                                                                                                                                     |
| **400** `Unsupported parameter: 'reasoning.effort'` (Codex)                          | A global `model_reasoning_effort` was sent to a non-reasoning model.                                                                                                         | Remove it, or use a reasoning model.                                                                                                                                                                                                                                               |
| **400** `Tool 'tool_search' is not supported with <model>` (Codex)                   | The small model rejects Codex's tools.                                                                                                                                       | Use a larger model.                                                                                                                                                                                                                                                                |
| **413** `Request body exceeds gateway limit`                                         | The request is larger than 16 MiB (large contexts or screenshots).                                                                                                           | Compact the conversation or start a new session.                                                                                                                                                                                                                                   |
| **415** `Unsupported request Content-Encoding`                                       | The request body is compressed (a `Content-Encoding` header other than `identity`). The gateway only accepts uncompressed bodies.                                             | Turn off request compression in the client.                                                                                                                                                                                                                                        |
| **502** `Upstream request failed`                                                    | The gateway couldn't reach the provider, or the provider connection failed mid-request.                                                                                      | Retry. The call is recorded as `ERROR`. Report it with the request ID if it persists.                                                                                                                                                                                              |
| **504** `Upstream deadline exceeded`, or a stream that stops                         | The call hit the 600-second overall limit, or the provider sent nothing for 120 seconds.                                                                                     | Known beta limits. Split very long generations. The call is recorded as `ERROR`.                                                                                                                                                                                                   |
| **503** `Gateway temporarily unavailable`                                            | The gateway is at capacity or briefly can't reach Langfuse.                                                                                                                  | Retry with backoff. Report it with the request ID if it persists.                                                                                                                                                                                                                  |
| Client crashes on the last chunk of a streamed Chat Completions response             | The gateway requests streaming usage upstream, so the stream ends with a usage chunk whose `choices` array is empty.                                                         | Skip chunks without choices. See [streaming usage](/docs/ai-gateway/features/api-formats#streaming-usage).                                                                                                                                                                         |

| Traces in `default` despite `langfuse-environment`                                   | The value doesn't match the environment format, so it fell back to `default`.                                                                                                | Use lowercase letters, numbers, `-` and `_`, at most 40 characters, not starting with `langfuse`.                                                                                                                                                                                  |

Anthropic `404` errors are not retried.                                                                                   | Fix the model ID. ## Reporting an issue [#reporting-an-issue]

Quote the **gateway request ID** when you report a problem. It identifies one call across the gateway logs and the recorded generation.

- Every response carries it in the `langfuse-request-id` header, including errors and streams. Print it with `curl -si … | grep -i '^langfuse-'`.
- Gateway error bodies also contain it as a top-level `request_id` field.
- If a generation was recorded, include the `langfuse-trace-id` header too, or the trace URL.
- In Langfuse, the same ID is stored on the generation as the metadata key `langfuse.gateway.request.id`.

Most coding agents don't show response headers. To get the request ID for an agent's call, open the generation in Langfuse and copy `langfuse.gateway.request.id` from its metadata, or reproduce the call with `curl`. See [response headers](/docs/ai-gateway/features/request-headers#response-headers).

## Known limitations [#known-limitations]

<Callout type="warning">
  These limits and known issues apply during the beta. Check them before you
  rely on gateway traces for audits or cost reporting.
</Callout>

- **Input over 5 MiB is not recorded.** When a request body exceeds 5 MiB, the generation has no input, and the metadata key `langfuse.gateway.request.input_omitted` says why (`size_limit`, with the limit in `langfuse.gateway.request.input_limit_bytes`). Output, usage, cost, and session are still recorded. Very long Codex and Claude Code sessions can hit this.
- **Output over 1 MiB is recorded partially.** The response still reaches the client in full, but the recorded output is cut and marked incomplete.
- **Cost bugs, fixes in progress:**
  - Failed and cancelled calls on the OpenAI route get estimated usage and cost. Long cancelled Codex calls showed about $6 each.
  - OpenAI `cache_write_tokens` are priced at $0.
  - Anthropic 1-hour cache writes are priced at the 5-minute rate, 37.5% too low.
- **One trace per model call by default** for Claude Code, OpenCode, and pi. Only Codex groups a turn into one trace out of the box. Use the Sessions view, or set up turn grouping for [Claude Code](/docs/ai-gateway/coding-agents/claude-code#turn-grouping), [OpenCode](/docs/ai-gateway/coding-agents/opencode#turn-grouping), or [pi](/docs/ai-gateway/coding-agents/pi#turn-grouping).
- **Generic names.** Generations are named after the API format (`anthropic.messages`, `openai.responses`), and trace names default to the agent name.
- **Duplicate metadata.** `attributes.user.id`, `attributes.session.id`, and `attributes.langfuse.trace.*` appear in metadata next to the canonical fields.
- **OpenCode:** title calls can't be told apart from agent steps, and subagents get a separate session.
- **Limits:** 16 MiB request body, 600 seconds per call, and 120 seconds without progress. There is no per-key or per-organization rate limit. Self-hosted deployments can change these limits, see [Self-hosting the AI Gateway](/self-hosting/configuration/ai-gateway#configuration).
- **No retries, fallbacks, or caching.** See [what the gateway doesn't do](/docs/ai-gateway/overview#limits).
- **Not served:** websockets and realtime APIs.
- **Decision models aren't supported.** The gateway doesn't serve the OpenAI Decisions API (`/v1/decisions`) or TypeSafe's System One API, and it has no TypeSafe provider credential. Requests to these endpoints return `404`. [Decision model evaluators](/docs/evaluation/evaluation-methods/decision-models) keep using their own [LLM connection](/docs/administration/llm-connection). Structured outputs (`response_format`, JSON schemas) on Chat Completions and Responses are passed through as usual.
- **Untested:** Anthropic server tools (web search and fetch) and interactive Codex `/compact`.

## FAQ [#faq]

### Does the gateway change my requests? [#does-the-gateway-change-requests]

Only where it has to. The gateway forwards the native provider request body with these changes:

- It removes the `<credential>:` prefix from `model`.
- It replaces the authentication headers with your organization's provider credential, and doesn't forward `langfuse-*` headers or your `x-request-id`.
- On streamed Chat Completions requests, it asks the provider for usage. See [streaming usage](/docs/ai-gateway/features/api-formats#streaming-usage).

The response is relayed unchanged. The gateway reads the request and response to record the generation.

### Can I use the gateway in USAGE mode and still set users and tags? [#usage-mode-headers]

Yes. [Request headers](/docs/ai-gateway/features/request-headers) work in both `FULL` and `USAGE` capture modes.

### Can I use the gateway together with the Langfuse SDK? [#sdk]

Yes. Send the W3C `traceparent` header of your current span with the request, and the gateway records its generation inside your trace. If your app uses OpenTelemetry, which the Langfuse SDKs are built on, an HTTP client instrumentation can inject the header for you. See [trace context and baggage](/docs/ai-gateway/features/request-headers#trace-context).

Don't also trace the same call with a provider SDK integration, such as the Langfuse OpenAI integration, or the call is recorded twice.

### How is gateway usage billed? [#pricing]

Each generation the gateway records counts as a [billable unit](/docs/administration/billable-units), like any other observation. Your provider bills model usage to your own provider account.

### Which provider credentials are used? [#which-credentials]

The organization's AI Gateway provider credentials. Your coding agent only needs the gateway key; it never sees the provider key.

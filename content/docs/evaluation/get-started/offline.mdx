# Get started with offline evaluation

Offline evaluations give you a repeatable way to measure the quality of your LLM application before shipping a change. In this quickstart, you will build a dataset of questions about sites in San Francisco, run an experiment, score each answer, and compare an improved prompt with the first run.

Every experiment in this guide has three parts:

- **Dataset**: Test cases with inputs and expected outputs
- **Task**: The application or model call you want to test
- **Evaluators**: Functions that score the task output

<Callout type="info">
  This guide uses the current Langfuse SDKs: **Python SDK v4** and **JS/TS SDK v5**. Both use Langfuse's OpenTelemetry-based tracing and the current experiment runner. If you use an older SDK, see the [Python v3 → v4](/docs/observability/sdk/upgrade-path/python-v3-to-v4) or [JS/TS v4 → v5](/docs/observability/sdk/upgrade-path/js-v4-to-v5) migration guide.
</Callout>

## 3. Create the dataset [#sdk-create-dataset]

Create a Langfuse dataset and add five questions with their expected answers. Run this setup script once; the experiment script in the next step reuses the stored dataset.

  {
    id: "evaluation-quickstart-sf-palace-of-fine-arts",
    input: {
      question:
        "Which Beaux-Arts landmark in the Marina District features a rotunda beside a lagoon?",
    },
    expectedOutput: "Palace of Fine Arts",
  },
  {
    id: "evaluation-quickstart-sf-coit-tower",
    input: {
      question: "Which Art Deco tower stands on Telegraph Hill?",
    },
    expectedOutput: "Coit Tower",
  },
  {
    id: "evaluation-quickstart-sf-lombard-street",
    input: {
      question:
        "Which San Francisco street is famous for a steep block with eight hairpin turns?",
    },
    expectedOutput: "Lombard Street",
  },
];

async function main() {
  await langfuse.api.datasets.create({
    name: datasetName,
    description: "Questions and expected answers about sites in San Francisco",
  });

  for (const item of items) {
    await langfuse.dataset.createItem({
      datasetName,
      ...item,
    });

}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});

## 4. Run an experiment [#sdk-run-experiment]

The task sends each question to the model. The evaluator returns `1` when the model output exactly matches the expected site name and `0` otherwise.

<LangTabs items={["Python SDK", "JS/TS SDK"]}>
<Tab>

```python filename="sf_sites.py"
from langfuse import Evaluation, get_client
from langfuse.openai import OpenAI

langfuse = get_client()
client = OpenAI()


def answer_question(*, item, **kwargs):
    question = item.input["question"]
    response = client.responses.create(
        model="gpt-5-mini",
        input=[
            {
                "role": "system",
                "content": "Answer the question about a site in San Francisco.",
            },
            {"role": "user", "content": question},
        ],
    )
    return response.output_text


def exact_match(*, output, expected_output, **kwargs):
    return Evaluation(
        name="exact_match",
        value=1.0 if output == expected_output else 0.0,
    )


try:
    dataset = langfuse.get_dataset("san-francisco-sites")
    result = dataset.run_experiment(
        name="San Francisco sites",
        run_name="San Francisco sites v1",
        description="First prompt for answering questions about San Francisco sites",
        task=answer_question,
        evaluators=[exact_match],
    )

    print(result.format())
finally:
    # Required for short-lived processes so all traces reach Langfuse.
    langfuse.flush()
```

Run the experiment:

```bash
python sf_sites.py
```

</Tab>
<Tab>

```typescript filename="sf-sites.ts"
import { LangfuseClient, type Evaluator } from "@langfuse/client";
import { observeOpenAI } from "@langfuse/openai";
import { LangfuseSpanProcessor } from "@langfuse/otel";
import { NodeSDK } from "@opentelemetry/sdk-node";
import OpenAI from "openai";

const otelSdk = new NodeSDK({
  spanProcessors: [new LangfuseSpanProcessor()],
});
otelSdk.start();

const langfuse = new LangfuseClient();
const client = observeOpenAI(new OpenAI());

const exactMatch: Evaluator = async ({ output, expectedOutput }) => ({
  name: "exact_match",
  value: output === expectedOutput ? 1 : 0,
});

async function main() {
  const dataset = await langfuse.dataset.get("san-francisco-sites");

  const result = await dataset.runExperiment({
    name: "San Francisco sites",
    runName: "San Francisco sites v1",
    description:
      "First prompt for answering questions about San Francisco sites",
    task: async (item) => {
      const { question } = item.input as { question: string };
      const response = await client.responses.create({
        model: "gpt-5-mini",
        input: [
          {
            role: "system",
            content: "Answer the question about a site in San Francisco.",
          },
          { role: "user", content: question },
        ],
      });

      return response.output_text;
    },
    evaluators: [exactMatch],
  });

  console.log(await result.format({ includeItemResults: true }));
}

main()
  .catch((error) => {
    console.error(error);
    process.exitCode = 1;
  })
  // Required for short-lived processes so all traces reach Langfuse.
  .finally(() => otelSdk.shutdown());
```

Run the experiment:

```bash
npx tsx sf-sites.ts
```

</Tab>
</LangTabs>

The experiment runner handles concurrent execution, traces each task, attaches evaluator scores, and creates a dataset run that you can inspect and compare in Langfuse.

## 5. View the results [#sdk-view-results]

The formatted terminal output includes the experiment summary and a link to the dataset run. You can also open [**Experiments**](https://cloud.langfuse.com/project/~/experiments) in Langfuse.

For each item, you can inspect:

- The dataset input and expected output
- The model's response
- The exact-match score
- The traced OpenAI call, including latency, token usage, and cost

## 6. Improve the prompt and compare [#sdk-iterate]

Exact match is intentionally strict. An answer such as `The answer is Coit Tower.` receives `0` because it does not exactly equal `Coit Tower`.

Change the run name to `San Francisco sites v2` and replace the system message with:

```text
Answer the question about a site in San Francisco. Return only the site's official name, with no additional text or punctuation.
```

Run the script again. Both runs use the same stored dataset, so you can compare aggregate scores and individual outputs side by side in the Experiments view.

## Troubleshooting [#sdk-troubleshooting]

### The dataset already exists

The setup script creates the dataset and is intended to run once. If `san-francisco-sites` already exists, skip the dataset creation call and keep the item-creation loop. Stable item IDs make those calls safe to repeat.

### The experiment is missing traces

Check your Langfuse environment variables. For Python, keep `langfuse.flush()` at the end of the script. For JS/TS, keep `otelSdk.shutdown()` so the short-lived process exports all buffered spans before it exits.

### Some exact-match scores are zero

Open the affected item and compare the model output with the expected output. Capitalization, extra words, and punctuation all cause exact match to fail. This is useful for deterministic output contracts; use [LLM-as-a-Judge](/docs/evaluation/evaluation-methods/llm-as-a-judge) when correctness requires semantic judgment.

## 1. Create a project and configure an LLM connection [#ui-create-project]

1. [Create a Langfuse account](/cloud) or [self-host Langfuse](/self-hosting).
2. Create a project.
3. Add an OpenAI API key under **Settings → LLM Connections**. See [LLM Connections](/docs/administration/llm-connection) for configuration details.

## 2. Create a prompt [#ui-create-prompt]

Open [**Prompt Management**](https://cloud.langfuse.com/project/~/prompts) and create a chat prompt named `san-francisco-site-answer`.

Add this system message:

```text
Answer the question about a site in San Francisco.
```

Add this user message:

```text
{{question}}
```

The `question` variable matches the key in each dataset item's input object.

## 3. Create the dataset [#ui-create-dataset]

1. Download the [San Francisco sites sample dataset](/files/san-francisco-sites.csv).
2. Open [**Datasets**](https://cloud.langfuse.com/project/~/datasets).
3. Create a dataset named `san-francisco-sites`.
4. Import the CSV. Map `input` to the dataset input and `expectedOutput` to the expected output.
5. Confirm that each input is a JSON object with a `question` field.

## 4. Add the Exact Match evaluator [#ui-create-evaluator]

1. Open [**Evaluators**](https://cloud.langfuse.com/project/~/evals) and select **New evaluator**.
2. In the evaluator gallery, select the Langfuse-maintained **Check if Output Is an Exact Match** template.
3. Keep the template definition unchanged and save the evaluator.
4. Continue without creating a production rule. You will select the evaluator directly when configuring the experiment.

The template compares the model output with the dataset item's expected output. Because this dataset stores each expected site name as a plain string, no mapping or code changes are required.

## 5. Run the experiment [#ui-run-experiment]

1. Open the `san-francisco-sites` dataset.
2. Select **Start Experiment** and create a prompt experiment.
3. Name it `San Francisco sites v1`.
4. Select the `san-francisco-site-answer` prompt and your OpenAI connection.
5. Select the Exact Match evaluator you created from the gallery.
6. Run the experiment.

Langfuse runs the prompt against every dataset item, stores the output and trace, applies the evaluator, and opens the completed experiment.

## 6. Improve the prompt and compare [#ui-iterate]

Create a new version of `san-francisco-site-answer` with this system message:

```text
Answer the question about a site in San Francisco. Return only the site's official name, with no additional text or punctuation.
```

Run a second experiment named `San Francisco sites v2`. Open [**Experiments**](https://cloud.langfuse.com/project/~/experiments) to compare both runs and inspect which dataset items improved or regressed.

# Model management

<AiGatewayBetaCallout />

As an admin, you can manage which models are allowed to be used. This page explains where the model list comes from, how admins choose models, and which model ID to send.

<Frame fullWidth>
  ![Providers & Models page on the Models tab with a searchable model list filtered to one provider credential, an Enabled switch per model, and Enable all and Disable all buttons](/images/docs/ai-gateway/models-manage.png)
</Frame>

## Supported providers [#supported-providers]

| Provider       | API formats                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------- |
| OpenAI         | OpenAI Responses, OpenAI Chat Completions                                                   |
| Anthropic      | Anthropic Messages                                                                          |
| Amazon Bedrock | Anthropic Messages for Claude models; OpenAI Responses or Chat Completions for other models |

### Amazon Bedrock [#amazon-bedrock]

A Bedrock credential takes an [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html) and an AWS region. The gateway lists the region's foundation models and system-defined inference profiles; to list them, the key needs `bedrock:ListFoundationModels` and `bedrock:ListInferenceProfiles`.

Bedrock model IDs always need the credential prefix, for example `bedrock-prod:<bedrock-model-id>`, because unprefixed `claude-` IDs never reach a Bedrock credential. For [cross-region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html), use the inference profile ID, for example `bedrock-prod:global.<bedrock-model-id>`.

## Available models [#available-models]

You can find a list of every model gateway keys can call under **AI Gateway → Providers & Models → Models**. Everyone with gateway access can open this page, including Viewers and the AI Gateway role.

The list comes from each provider credential: the gateway pings the provider's own `/models` endpoint to check which models the credential can access.

<Callout type="warning">
  If a provider rejects a credential during model discovery, for example
  because the key was rotated, the credential is marked as failing and the
  gateway stops routing to it. Update the key or select **Retry** in
  **AI Gateway → Providers & Models → Providers** to restore it.
</Callout>

## Manage models [#manage-models]

Gateway managers (Owners and Admins) can configure models per provider credential:

1. Go to **AI Gateway → Providers & Models → Models** and select a provider credential.
2. Turn models on or off with the **Enabled** switch.
3. Select **Refresh provider models** to fetch the provider's current list.

A credential with every model enabled also allows models that the provider publishes later. As soon as you turn one model off, the credential keeps an explicit list. Select **Enable all** to go back to allowing every model.

## Model IDs [#model-ids]

Model IDs have the form `<credential>:<model>`, for example `openai-prod:<model>`, so the gateway knows which credential to use. For coding agents that send the provider's own model names, IDs without a prefix also work if they start with `gpt-`, `codex-`, `ft:`, or `claude-`, and the gateway uses the oldest matching credential. Renaming a credential changes its prefix, so update clients that use the old IDs.

## Troubleshooting and FAQ [#troubleshooting-and-faq]

<FaqDetails>

<Details id="new-models">
<Summary>Why can't I call a new model?</Summary>

A model the provider just released is available right away only on credentials that have every model enabled. If an admin turned off any model on a credential, the credential keeps an explicit list, and new models stay off until an admin enables them under **AI Gateway → Providers & Models → Models**. Select **Refresh provider models** there if the model doesn't appear in the list yet.

</Details>

</FaqDetails>

# Model management

<AiGatewayBetaCallout />

As an admin, you can manage which models are allowed to be used. This page explains where the model list comes from, how admins choose models, and which model ID to send.

## Supported providers [#supported-providers]

| Provider          | API formats                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------- |
| OpenAI            | OpenAI Responses, OpenAI Chat Completions                                                   |
| Anthropic         | Anthropic Messages                                                                          |
| Amazon Bedrock    | Anthropic Messages for Claude models; OpenAI Responses or Chat Completions for other models |
| OpenRouter        | OpenAI Responses, OpenAI Chat Completions, Anthropic Messages                               |
| Vercel AI Gateway | OpenAI Responses, OpenAI Chat Completions, Anthropic Messages                               |
| xAI               | OpenAI Responses, OpenAI Chat Completions                                                   |

## Available models [#available-models]

You can find a list of every model gateway keys can call under **AI Gateway → Providers & Models → Models**. Everyone with gateway access can open this page, including Viewers and the AI Gateway role.

The list comes from each provider credential: the gateway pings the provider's own `/models` endpoint to check which models the credential can access.

<Callout type="warning">
  If a provider rejects a credential during model discovery, for example
  because the key was rotated, the credential is marked as failing and the
  gateway stops routing to it. Update the key or select **Retry** in
  **AI Gateway → Providers & Models → Providers** to restore it.
</Callout>

## Manage models [#manage-models]

Gateway managers (Owners and Admins) can configure models per provider credential:

1. Go to **AI Gateway → Providers & Models → Models** and select a provider credential.
2. Turn models on or off with the **Enabled** switch.
3. Select **Refresh provider models** to fetch the provider's current list.

A credential with every model enabled also allows models that the provider publishes later. As soon as you turn one model off, the credential keeps an explicit list. Select **Enable all** to go back to allowing every model.

## Model IDs [#model-ids]

Every request names a model. You can send it in two forms: a credential-scoped model ID, which picks the credential explicitly, or a plain model name, which lets the gateway pick the credential.

### Credential-scoped model IDs [#credential-scoped-model-ids]

A credential-scoped model ID has the form `<credential>:<model>`. `<credential>` is the name you gave the provider credential, and `<model>` is the model ID in that provider's own naming. For example:

- `openai-prod:<model>` calls `<model>` with the credential named `openai-prod`.
- `openrouter:openai/<model>` calls OpenRouter's `openai/<model>` with the credential named `openrouter`.

Use this form whenever your client lets you set the model ID. It's the only form that works for OpenRouter, Vercel AI Gateway, xAI, and Amazon Bedrock credentials, and the only way to choose between several credentials that offer the same model. Renaming a credential changes its prefix, so update clients that use the old IDs.

### Model names without a prefix [#model-names-without-a-prefix]

Some coding agents don't read the gateway's model list and always send the provider's plain model name, for example `gpt-<version>` or `claude-<version>`. The gateway accepts a name without a prefix only if it starts with `gpt-`, `codex-`, or `ft:` (served by an OpenAI credential) or `claude-` (served by an Anthropic credential). It rejects any other name without a prefix.

If your organization has several credentials that could serve the model, the gateway picks one like this:

1. It considers only OpenAI or Anthropic credentials, matching the name, that support the API format of the request path and aren't failing. OpenRouter, Vercel AI Gateway, xAI, and Amazon Bedrock credentials are never picked for a name without a prefix, even if they offer the same model.
2. Of those, it uses the oldest credential, the one added first, that has the model enabled.
3. If none of them has the model enabled, the request fails with a `model_not_allowed` error.

<Callout type="warning">
  The gateway sends each request to exactly one credential. If that credential
  fails, for example because the provider returns an error or a rate limit,
  the gateway doesn't retry the request with another credential. To control
  which credential serves a request, send a credential-scoped model ID.
</Callout>

## Troubleshooting and FAQ [#troubleshooting-and-faq]

<FaqDetails>

<Details id="new-models">
<Summary>Why can't I call a new model?</Summary>

A model the provider just released is available right away only on credentials that have every model enabled. If an admin turned off any model on a credential, the credential keeps an explicit list, and new models stay off until an admin enables them under **AI Gateway → Providers & Models → Models**. Select **Refresh provider models** there if the model doesn't appear in the list yet.

</Details>

<Details id="bedrock-models">
<Summary>Why doesn't my Amazon Bedrock credential list any models?</Summary>

A Bedrock credential takes an [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html) and an AWS region. To list models, the key needs the `bedrock:ListFoundationModels` and `bedrock:ListInferenceProfiles` permissions. Otherwise, add custom models to the credential on its models page. For [cross-region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html), use the inference profile ID as the model, for example `bedrock-prod:global.<bedrock-model-id>`.

</Details>

</FaqDetails>

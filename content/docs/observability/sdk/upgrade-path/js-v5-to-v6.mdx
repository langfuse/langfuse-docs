# JS/TS v5 → v6

For most users, v6 is a small upgrade. If you trace with `startActiveObservation()`, `observe()`, or an integration, and you create scores and fetch prompts through the managers (`langfuse.prompt`, `langfuse.score`, `langfuse.dataset`), your code keeps working as is. v6 needs Node.js 22+ and Langfuse Cloud or self-hosted Langfuse v4.55.0 or later.

All `@langfuse/*` packages are released together. Upgrade them to the same major version:

```bash
npm install @langfuse/client@6 @langfuse/tracing@6 @langfuse/otel@6
```

`baseUrl`, `LANGFUSE_BASE_URL`, and `LANGFUSE_BASEURL` keep working as before.

## Are you affected? [#are-you-affected]

You only need to change something if one of these applies to you:

- **You self-host Langfuse v3, or v4 older than v4.55.0**, or run Node.js older than 22, or use `@langchain/core` older than 1.0 → [Minimum versions](#minimum-versions)
- **You call top-level `LangfuseClient` methods** such as `getPrompt()`, `getDataset()`, or `fetchTrace()` → [Deprecated `LangfuseClient` aliases removed](#client-aliases-removed)
- **You call `langfuse.api.*` directly**, for example `api.trace.get`, `api.sessions`, `api.legacy.*`, `api.scores.getMany`, or the response of `api.scores.create` → [Removed Public API methods](#removed-public-api-methods)
- **You pass `requestOptions` to a generated API method without query parameters or a body**, such as `api.datasets.get(name, { timeoutInSeconds })` → [Request placeholder before `requestOptions`](#request-placeholder)
- **You call `setActiveTraceIO()`, `span.setTraceIO()`, or `createTraceAttributes()`** → [Trace input/output setters removed](#trace-io-setters-removed)
- **You call `item.link()` on dataset items** → [Dataset item `link()` removed](#dataset-item-link-removed)
- **A proxy between your app and Langfuse rejects gzip-compressed requests** → [Under the hood](#under-the-hood)

If none of these apply, upgrade and you're done.

## Breaking changes [#breaking-changes]

Ordered by how many users they affect.

### Minimum versions [#minimum-versions]

**Affects:** self-hosted Langfuse v3 or older than v4.55.0, Node.js older than 22, and the LangChain integration on LangChain 0.x.

| Requirement | v6                                         | If not met                                                                      |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------------- |
| Langfuse    | Cloud, or self-hosted **v4.55.0 or later** | Score batches are rejected and the scores dropped                               |
| Node.js     | `>=22`, packages compiled to ES2022        | Unsupported. Bundles for older runtimes must target ES2022 or transpile the SDK |
| LangChain   | `@langchain/core@^1.0.0` (was `>=0.3.8`)   | Peer dependency conflict when installing `@langfuse/langchain@6`                |

If you self-host Langfuse v3, stay on JS/TS SDK v5. See the [self-hosted compatibility matrix](/self-hosting/upgrade/versioning#sdk-server).

```bash
npm install @langfuse/langchain@6 @langchain/core@^1
```

The `CallbackHandler` API and trace output are unchanged.

### Deprecated `LangfuseClient` aliases removed [#client-aliases-removed]

**Affects:** code that calls the top-level convenience methods on `LangfuseClient`.

**Breaks:** a TypeScript compile error, or `TypeError: ... is not a function` in JavaScript. Use the managers or the `api` client instead.

| Removed                                | Replacement                                                   |
| -------------------------------------- | ------------------------------------------------------------- |
| `langfuse.getPrompt(...)`              | `langfuse.prompt.get(...)`                                    |
| `langfuse.createPrompt(...)`           | `langfuse.prompt.create(...)`                                 |
| `langfuse.updatePrompt(...)`           | `langfuse.prompt.update(...)`                                 |
| `langfuse.getDataset(...)`             | `langfuse.dataset.get(...)`                                   |
| `langfuse.createDatasetItem(...)`      | `langfuse.dataset.createItem(...)`                            |
| `langfuse.resolveMediaReferences(...)` | `langfuse.media.resolveReferences(...)`                       |
| `langfuse.createDataset(...)`          | `langfuse.api.datasets.create(...)`                           |
| `langfuse.getDatasetItem(id)`          | `langfuse.api.datasetItems.get(id)`                           |
| `langfuse.fetchMedia(id)`              | `langfuse.api.media.get(id)`                                  |
| `langfuse.fetchTrace(id)`              | `langfuse.api.observations.getMany({ traceId: id, ... })`     |
| `langfuse.fetchTraces(...)`            | `langfuse.api.observations.getMany({ ... })`                  |
| `langfuse.fetchObservation(id)`        | `langfuse.api.observations.getMany({ filter: ..., ... })`     |
| `langfuse.fetchObservations(...)`      | `langfuse.api.observations.getMany(...)`                      |
| `langfuse.fetchSessions(...)`          | `langfuse.api.observations.getMany({ sessionId, ... })`       |
| `langfuse.getDatasetRun(...)`          | `langfuse.api.experiments.list(...)` and `.listItems(...)`    |
| `langfuse.getDatasetRuns(...)`         | `langfuse.api.experiments.list({ datasetId, fromStartTime })` |

**v5:**

```typescript
const prompt = await langfuse.getPrompt("support-agent");
const trace = await langfuse.fetchTrace("trace-id");
```

**v6:**

```typescript
import { LangfuseClient } from "@langfuse/client";

const langfuse = new LangfuseClient();

const prompt = await langfuse.prompt.get("support-agent");
const observations = await langfuse.api.observations.getMany({
  traceId: "trace-id",
  fields: "core,basic,io",
});
```

### Removed Public API methods [#removed-public-api-methods]

**Affects:** code that calls `langfuse.api.*` directly.

**Breaks:** TypeScript compile errors, or `TypeError` / `undefined` at runtime in JavaScript.

The generated client no longer includes the endpoints that Langfuse v4 deprecated, and there is no `api.legacy` namespace anymore. For full replacement guidance, see the [SDK method quick reference](/faq/all/deprecated-api-migration#sdk-method-quick-reference).

| Removed                                              | Replacement                                                          |
| ---------------------------------------------------- | -------------------------------------------------------------------- |
| `api.trace.get(...)`, `api.trace.list(...)`          | `api.observations.getMany({ traceId, ... })`                         |
| `api.sessions.*`                                     | `api.observations.getMany({ sessionId, ... })`                       |
| `api.legacy.observationsV1.*`                        | `api.observations.getMany(...)`                                      |
| `api.legacy.metricsV1.metrics(...)`                  | `api.metrics.metrics(...)`                                           |
| `api.legacy.scoreV1.create(...)`                     | `api.scores.create(...)`                                             |
| `api.legacy.scoreV1.delete(scoreId)`                 | `api.scores.delete(scoreId)`                                         |
| `api.scores.getMany(...)`, `api.scores.getById(...)` | `api.scoresV3.getManyV3(...)`                                        |
| `api.datasetRunItems.*`                              | `api.experiments.listItems(...)` or the experiment runner            |
| `api.datasets.getRun(...)`, `.getRuns(...)`          | `api.experiments.list(...)` and `.listItems(...)`                    |
| `api.datasets.deleteRun(...)`                        | List experiment items, then `api.trace.deleteMultiple({ traceIds })` |

Removed types include the trace, session, v1 observation, dataset run, and dataset run item response types, the `ScoreV1` family, `SdkLogEvent`, and the `legacy.CreateScoreRequest`, `legacy.CreateScoreResponse`, and `legacy.CreateScoreSource` re-exports. Use the score types without the `legacy` prefix.

`api.scores.create()` now accepts a single `CreateScoreRequest` or an array, and returns `CreateScoresResponse`, a union of the single-score and batch responses. Single-score calls keep working, but TypeScript code that reads fields from the response needs to narrow the type first.

**v5:**

```typescript
const { id } = await langfuse.api.scores.create({
  name: "accuracy",
  value: 0.9,
  traceId: "trace-id",
});
await langfuse.api.legacy.scoreV1.delete("score-id");
```

**v6:**

```typescript
import { LangfuseClient } from "@langfuse/client";

const langfuse = new LangfuseClient();

const response = await langfuse.api.scores.create({
  name: "accuracy",
  value: 0.9,
  traceId: "trace-id",
});
if ("id" in response) {
  console.log(response.id);
}
await langfuse.api.scores.delete("score-id");
```

To delete an experiment's data, page through its items and delete their traces. This also deletes their observations and scores:

```typescript
import { LangfuseClient } from "@langfuse/client";

const langfuse = new LangfuseClient();
const dataset = await langfuse.dataset.get("qa-set");
// No experiment item starts before its dataset was created, so this covers every run.
const fromStartTime = dataset.createdAt;

const traceIds = new Set<string>();
let cursor: string | undefined;
do {
  const page = await langfuse.api.experiments.listItems({
    datasetId: dataset.id,
    experimentName: "baseline",
    fromStartTime,
    cursor,
  });
  page.data.forEach((item) => traceIds.add(item.traceId));
  cursor = page.meta.cursor ?? undefined;
} while (cursor);

const ids = [...traceIds];
for (let i = 0; i < ids.length; i += 1000) {
  await langfuse.api.trace.deleteMultiple({ traceIds: ids.slice(i, i + 1000) });
}
```

See [Dataset runs → Experiments](/faq/all/deprecated-api-migration#dataset-runs) for details.

### Request placeholder before `requestOptions` [#request-placeholder]

**Affects:** calls that pass `requestOptions` to a generated API method that takes no query parameters and no body.

**Breaks:** a TypeScript compile error. In plain JavaScript the options are ignored. These methods now take an empty request object before `requestOptions`, so `requestOptions` keeps its position if the endpoint gains query parameters later. Calls without `requestOptions` don't change.

**v5:**

```typescript
await langfuse.api.datasets.get("qa-set", { timeoutInSeconds: 10 });
await langfuse.api.health.health({ maxRetries: 0 });
```

**v6:**

```typescript
await langfuse.api.datasets.get("qa-set", {}, { timeoutInSeconds: 10 });
await langfuse.api.health.health({}, { maxRetries: 0 });
```

### Trace input/output setters removed [#trace-io-setters-removed]

**Affects:** code that calls `setActiveTraceIO()`, `span.setTraceIO()`, or `createTraceAttributes()`, or uses the `LangfuseTraceAttributes` type.

**Breaks:** a TypeScript compile error, or a missing-export / `TypeError` at runtime. These were deprecated in v5. Trace input and output now come from the root observation.

**v5:**

```typescript
import { startActiveObservation, setActiveTraceIO } from "@langfuse/tracing";

await startActiveObservation("request", async () => {
  const result = await callLlm(query);
  setActiveTraceIO({ input: query, output: result });
});
```

**v6:**

```typescript
import {
  startActiveObservation,
  updateActiveObservation,
} from "@langfuse/tracing";

await startActiveObservation("request", async (span) => {
  const result = await callLlm(query);
  span.update({ input: query, output: result });
  // or, inside the active root observation:
  // updateActiveObservation({ input: query, output: result });
});
```

`setActiveTraceAsPublic()` and `span.setTraceAsPublic()` are unchanged. If you still use [trace-level LLM-as-a-judge evaluators](/faq/all/llm-as-a-judge-migration), migrate them to observation-level evaluators.

### Dataset item `link()` removed [#dataset-item-link-removed]

**Affects:** code that calls `item.link()` or uses the `LinkDatasetItemFunction` type.

**Breaks:** a TypeScript compile error, or `TypeError: item.link is not a function`. `dataset.items` is now a plain `DatasetItem[]`. Use the experiment runner to run your application on a dataset.

**v5:**

```typescript
const dataset = await langfuse.dataset.get("qa-set");

for (const item of dataset.items) {
  await startActiveObservation("qa-task", async (span) => {
    const output = await myApp(item.input);
    span.update({ input: item.input, output });
    await item.link(span, "baseline");
  });
}
```

**v6:**

```typescript
const dataset = await langfuse.dataset.get("qa-set");

const result = await dataset.runExperiment({
  name: "baseline",
  task: async (item) => myApp(item.input),
  evaluators: [accuracy],
});

console.log(result.experimentUrl);
```

See [Experiments via SDK](/docs/evaluation/experiments/experiments-via-sdk) for the full runner API.

## New features [#new-features]

These need no code changes.

- **Experiment links.** `result.experimentUrl` links directly to the experiment comparison view. `LangfuseClient` also exposes `getProjectId()` and `getExperimentUrl(experimentId)`.
- **Typed metadata filters.** On Langfuse v4.55.0 and later, numeric and boolean metadata keeps its type, and nested objects can be filtered by dotted path, such as `a.b = 1`. `propagateAttributes({ metadata })` accepts any JSON-serializable value.
- **Batch score creation.** `api.scores.create()` accepts an array of `CreateScoreRequest` objects.
- **Experiment records.** Run evaluations are sent for local-data runs too. Dataset versions (`datasetVersion`) are recorded on items as `langfuse.experiment.item.version`.

## Under the hood [#under-the-hood]

None of these need code changes. Each one has a setting if you need different behavior.

- **Scores are sent in batches of up to 100 to `POST /api/public/scores`** instead of the legacy ingestion endpoint. `langfuse.score.create()`, `.observation()`, `.trace()`, `flush()`, `shutdown()`, and the batching settings work as before. If the server accepts only part of a batch (HTTP 207), the SDK logs `Langfuse rejected N of M scores in batch:` with the server's errors and doesn't retry the rejected scores. Servers older than v4.55.0 reject score batches, and those scores are dropped. Each score carries the time it was queued as its timestamp. The server records it from Langfuse v4.59.0. v4.55.0 to v4.58.x record the time they received the score. `LangfuseBrowserClient.score()` also sends each score to `POST /api/public/scores`, with public-key authentication.
- **Score methods never throw.** Input is validated on the client. Scores with an empty name or a non-finite or non-string value are logged at error level and dropped.
- **Span batches are gzip-compressed on Node.js and Bun.** If a proxy rejects compressed requests, pass `new LangfuseSpanProcessor({ compression: "none" })` or set `LANGFUSE_OTEL_COMPRESSION=none`. The setting is read in this order: `compression`, `LANGFUSE_OTEL_COMPRESSION`, `OTEL_EXPORTER_OTLP_TRACES_COMPRESSION`, `OTEL_EXPORTER_OTLP_COMPRESSION`, then the `gzip` default. Values are `gzip` or `none`. Environment variables are case-insensitive, and an invalid value falls through to the next setting. Browser and edge runtimes ignore it.
- **Spans carry `x-langfuse-ingestion-version: 4`**, which enables real-time processing on Langfuse v4. To opt out, pass `additionalHeaders: { "x-langfuse-ingestion-version": "3" }` to `LangfuseSpanProcessor`. `additionalHeaders` override default headers case-insensitively.
- **Experiments are recorded through OpenTelemetry.** The experiment runner sends experiment and item attributes on its spans instead of calling `POST /api/public/dataset-run-items`.

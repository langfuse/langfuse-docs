# Skill Management concepts

A skill packages instructions and supporting files for a task. Langfuse follows the open [Agent Skills format](https://agentskills.io/specification) and versions each skill's files together.

## Skill structure [#skill-structure]

Every skill has a root `SKILL.md`. You can organize supporting material in folders such as `references/` or `scripts/`:

```text
refund-policy/
├── SKILL.md
├── references/
│   └── eligibility.md
└── scripts/
    └── check-order.py
```

Put the workflow in `SKILL.md`, detailed rules in reference files, and executable steps in scripts. Link to supporting files with paths relative to the skill folder.

## Frontmatter and instructions [#frontmatter]

`SKILL.md` starts with YAML frontmatter between `---` lines, followed by Markdown instructions:

```markdown filename="refund-policy/SKILL.md"
---
name: refund-policy
description: Review refund requests and explain eligibility. Use when a customer asks for a refund.
---

# Handle a refund request

1. Find the customer's order and purchase date.
2. Read [the eligibility rules](references/eligibility.md).
3. Explain the outcome and the next step to the customer.
```

The required `name` identifies the skill in your Langfuse project. The required `description` tells an agent what the skill does and when to use it. Langfuse preserves additional frontmatter; your agent framework determines how fields such as `allowed-tools` are interpreted.

## Loading a skill progressively [#progressive-loading]

An agent can load skills in stages:

1. Read skill names and descriptions to find a relevant skill.
2. Read that skill's `SKILL.md` instructions.
3. Open reference files or run scripts as the task requires.

Your agent framework provides the skill list, file-reading tools, and script execution. Langfuse stores and serves the files; it does not decide when your agent should load a skill.

## Versions [#versions]

A version saves all of a skill's files together. To change a saved version's instructions or supporting files, publish a new version. Each skill has its own version numbers, such as `refund-policy` version `2`.

The API returns a **manifest** containing the skill's name, description, version, and file list. Each file has a path and a content hash. A path identifies a file within the skill; a hash identifies its contents. You can fetch only the files you need and reuse content you have already cached. See [API loading](/docs/skill-management/load-skills#api-fetch).

## Labels [#labels]

A label points to a version. Use `staging` for testing and `production` for deployed agents. When you move a label, the next request for that label returns the newly assigned version. Files already fetched stay unchanged.

Langfuse assigns `latest` to the most recently created version. Assign `production` explicitly before requesting it. A missing label returns an error; Langfuse does not substitute `latest`. To pin a revision, request its version number.

## Tags [#tags]

Tags such as `support` or `billing` group skills across their versions. Use them to filter the skill list or install several skills with the CLI. Labels select a version of each skill.

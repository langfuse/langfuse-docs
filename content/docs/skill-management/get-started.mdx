# Get Started with Skill Management

This guide walks you through creating and using a skill with Langfuse. If you're looking to understand what skill management is and why it matters, check out the [Skill Management Overview](/docs/skill-management/overview) first. For details on how skills are structured in Langfuse and how it works in the background, see [Core Concepts](/docs/prompt-and-skill-management/concepts).

## Manual installation [#manual-installation]

This guide helps you get started with Langfuse Skill Management manually.

<Steps>

### Get API keys [#get-api-keys]

1.  [Create Langfuse account](https://langfuse.com/cloud) or [self-host Langfuse](/self-hosting).
2.  Create new API credentials in the project settings.

For the CLI and API examples, export your project credentials and Langfuse URL:

```bash
export LANGFUSE_PUBLIC_KEY="pk-lf-..."
export LANGFUSE_SECRET_KEY="sk-lf-..."
export LANGFUSE_BASE_URL="https://cloud.langfuse.com"
```

### Create a skill [#create-a-skill]

<Tabs items={["UI", "CLI", "Python SDK", "JS/TS SDK", "API"]}>
<Tab>

If **Skills** is not visible, enable **Skill Management** under **account menu → Feature Preview**. Enable **V4 Preview** first if its toggle is disabled.

1. Open **Skills → New skill → Create from scratch**.
2. Add your instructions to `SKILL.md`, including the required `name` and `description` frontmatter.
3. Click **Publish**, then confirm with **Create skill**.
4. Open **Labels** on the saved version, select `production`, and click **Save and promote to production**.

![The skill editor showing files, version history, and labels.](/images/changelog/2026-10-22-skill-management-editor.jpg)

</Tab>
<Tab>

Install the CLI:

```bash
npm install -g @langfuse/cli
mkdir -p skill_name
```

Save your skill locally, for example as `skill_name/SKILL.md`. Publish the folder and assign `production`:

```bash
langfuse skills push ./skill_name --label production
```

The command prints the saved version. See [version control](/docs/skill-management/version-control) for API publishing and label management.

</Tab>
<Tab>

Create a version from `SKILL.md` and assign the `production` label:

```python
from langfuse import Langfuse
from langfuse.api.skills import SkillVersionFileInput

langfuse = Langfuse()
skill = langfuse.api.skills.create_version(files=[
    SkillVersionFileInput(path="SKILL.md", content="""---
name: skill_name
description: Describe when to use this skill.
---
Instructions for the agent.
"""),
])
langfuse.api.skills.set_labels(skill.name, skill.version, labels=["production"])
```

</Tab>
<Tab>

Create a version from `SKILL.md` and assign the `production` label:

```typescript
import { LangfuseClient } from "@langfuse/client";

const langfuse = new LangfuseClient();
const skill = await langfuse.api.skills.createVersion({
  files: [{
    path: "SKILL.md",
    content: `---
name: skill_name
description: Describe when to use this skill.
---
Instructions for the agent.
`,
  }],
});
await langfuse.api.skills.setLabels(skill.name, skill.version, {
  labels: ["production"],
});
```

</Tab>
<Tab>

Send `SKILL.md` to create a version:

```bash
curl --request POST "$LANGFUSE_BASE_URL/api/public/skills" \
  --user "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "files": [{
      "path": "SKILL.md",
      "content": "---\nname: skill_name\ndescription: Describe when to use this skill.\n---\nInstructions for the agent."
    }]
  }'
```

Set `SKILL_VERSION` to the response's `version`, then assign `production` so the loading examples below can retrieve it:

```bash
curl --request PATCH \
  "$LANGFUSE_BASE_URL/api/public/skills/skill_name/versions/$SKILL_VERSION" \
  --user "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  --header "Content-Type: application/json" \
  --data '{"labels":["production"]}'
```

See the [Skills API reference](https://api.reference.langfuse.com/#tag/skills) for request and response fields.

</Tab>
</Tabs>

### Use your skill [#load-your-skill]

Install skill folders for an agent that reads files from disk, or fetch file contents with an SDK or the REST API. Pass the fetched instructions and supporting files to your agent's skill loader.

<Tabs items={["CLI", "Python SDK", "JS/TS SDK", "API"]} defaultIndex={0}>
<Tab>

#### Install with the CLI [#cli-install]

Install the CLI, then download the version labeled `production`:

```bash
npm install -g @langfuse/cli
langfuse skills install skill_name --label production
```

The CLI writes files to `.agents/skills/skill_name/` by default. Configure your agent to read that directory. Installation alone does not make the model use the skill.

In the UI, **Use skill → Install with CLI → Configure install command** builds a command for one skill, a tag, or all project skills. Choose a label or version and an installation directory, then copy the command or setup prompt for your coding agent.

To pin a version or install a group of skills:

```bash
langfuse skills install skill_name --version 2
langfuse skills install --tag tag
```

Keep the `langfuse-skills.lock` file reported by the CLI to restore the resolved versions. The CLI looks for it in the installation directory, then the working directory. See the [CLI reference](https://github.com/langfuse/langfuse-cli#readme) for directory and lockfile options.

##### Restore or update [#restore-or-update]

```bash
langfuse skills install
langfuse skills update
```

`install` without arguments restores locked versions. `update` updates already locked skills to the versions assigned to their saved labels; exact version pins stay fixed. Run `install --tag tag` or `install --all` again to include newly added skills.

</Tab>
<Tab>

#### Fetch with the Python SDK [#python-sdk]

Fetch the version labeled `production` with its file contents:

```python
from langfuse import Langfuse

langfuse = Langfuse()
skill = langfuse.api.skills.get(
    "skill_name", label="production", include_content=True,
)
instructions = next(file.content for file in skill.files if file.path == "SKILL.md")
if instructions is None:
    raise ValueError("Skill instructions were not returned")
print(instructions)
```

Each entry in `skill.files` includes a `path` and `content`. Use the same response to read supporting files from this version.

</Tab>
<Tab>

#### Fetch with the JavaScript/TypeScript SDK [#javascript-sdk]

Fetch the version labeled `production` with its file contents:

```typescript
import { LangfuseClient } from "@langfuse/client";

const langfuse = new LangfuseClient();
const skill = await langfuse.api.skills.get("skill_name", {
  label: "production",
  includeContent: true,
});
const instructions = skill.files.find((file) => file.path === "SKILL.md")?.content;
if (instructions === undefined) throw new Error("Skill instructions were not returned");
console.log(instructions);
```

Each entry in `skill.files` includes a `path` and `content`. Use the same response to read supporting files from this version.

</Tab>
<Tab>

#### Fetch through the API [#api-fetch]

Fetch the version labeled `production` with its file contents:

```bash
curl --get "$LANGFUSE_BASE_URL/api/public/skills/skill_name" \
  --user "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  --data-urlencode "label=production" \
  --data-urlencode "includeContent=true"
```

The response includes the skill's `name`, `version`, and `files`. Each file has a `path`, `sha256Hash`, and `content`. Read `SKILL.md` for the instructions and other files as your agent needs them. See the [Skills API reference](https://api.reference.langfuse.com/#tag/skills) for request and response fields.

<Details>
<Summary>Fetch files on demand</Summary>

##### Resolve the version [#resolve-the-version]

Omit `includeContent` to fetch a manifest without file contents:

```bash
curl --get "$LANGFUSE_BASE_URL/api/public/skills/skill_name" \
  --user "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  --data-urlencode "label=production"
```

##### Read a file [#read-a-file]

Set `SKILL_FILE_HASH` to a file's `sha256Hash` from the manifest. Use `--data-urlencode` to encode the base64 hash correctly:

```bash
curl --get "$LANGFUSE_BASE_URL/api/public/skills/files/content" \
  --user "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" \
  --data-urlencode "sha256Hashes=$SKILL_FILE_HASH"
```

The response's `data` array contains `{ sha256Hash, content }` objects. Match results to manifest files by hash. Send up to 50 unique hashes as a comma-separated `sha256Hashes` value to fetch several files. Cache content by hash to reuse it across requests.

</Details>

</Tab>
</Tabs>

For SDK and API requests, pass `version` instead of `label` to select a fixed version. Omitting both selects `production`. Keep the resolved version fixed during a run so instructions and supporting files come from the same revision.

</Steps>

## Work at the level agents run [#workflows]

Agentic traces can contain hundreds or thousands of operations. The useful answer is often inside one model call, tool execution, or sub-agent—not at the top of the trace.

V4 makes observations the primary entity, so you can start with the question you want to answer and query the relevant operations directly.

<V4WorkflowGrid />

## One table, every operation [#data-model]

V4 stores every operation as an immutable observation. Trace attributes live on each row, while `trace_id` groups related observations into a trace.

This removes costly joins and read-time deduplication from the most common queries. Tables, dashboards, APIs, and evaluations stay responsive as traces and projects grow.

<ObservationsTableDiagram />

<Callout type="info" title="Input and output live on observations">
Trace-level input and output are deprecated. Tables, evaluators, and exports now use the relevant observation—usually the root span or LLM call—so the selected data is precise and loads faster.
</Callout>

## Rollout timeline [#timeline]

The timeline shows when V4 features become the only experience on Langfuse Cloud and when V4 reaches self-hosted deployments.

<VersionTimeline />

<Details>
<Summary>Cloud rollout details</Summary>

- Organizations created on or after April 14, 2026, 14:00 UTC run v4 by default and do not see a toggle.
- Organizations created before that date can switch the **Preview** toggle in the bottom-left of the UI until Langfuse Cloud becomes v4-only.
- Cloud projects created on or after May 20, 2026 use the enriched observations export source. New legacy export integrations cannot be created.

</Details>

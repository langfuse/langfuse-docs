# Why do I get "Blocked IP address detected"?

Langfuse calls some user-configured URLs on your behalf: LLM connection base URLs, webhook targets, blob storage export endpoints, and external media storage endpoints. To prevent server-side request forgery (SSRF), it resolves the hostname and rejects the URL with `Blocked IP address detected` when any resolved IP is in a private, loopback, link-local, or otherwise reserved range (for example `10.0.0.0/8`, `192.168.0.0/16`, `127.0.0.0/8`, or `169.254.0.0/16`). Hostnames such as `localhost`, `*.internal`, and `host.docker.internal` fail with `Blocked hostname detected`. A hostname that does not resolve fails as well.

The check runs when you save the setting and again on every request and redirect.

<Callout type="info">
  On IPv6-only networks with DNS64, even public provider hostnames can resolve to the NAT64 range `64:ff9b::/96`. Langfuse blocks this range, so a public endpoint can fail with this error too. Allow the host explicitly (see [Outbound URL allowlists](/self-hosting/configuration/hardening#outbound-url-allowlists)) or give the Langfuse containers IPv4 egress.
</Callout>

## Langfuse Cloud

The check is always enforced and cannot be relaxed. LLM connection base URLs must use `https://`. Point the connection at a publicly resolvable endpoint, for example a gateway with a public hostname.

## Self-hosted Langfuse

On self-hosted Langfuse, allow specific internal endpoints with the per-feature allowlist environment variables. Set them on both the web and worker containers, because both make outbound requests.

<Callout type="warning">
  There is no setting that turns the check off for all targets. Every internal endpoint has to be listed explicitly, because anything on these lists is exempt from SSRF protection.
</Callout>

See [Outbound URL allowlists](/self-hosting/configuration/hardening#outbound-url-allowlists) for the variables, including the positive `*_ALLOWED_HOSTS` allowlists, and [LLM connection troubleshooting](/docs/administration/llm-connection#blocked-ip-address) for LLM connections.

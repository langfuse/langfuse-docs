# How do I evaluate webhook or SDK experiments with Langfuse evaluators?

Langfuse-managed evaluators ([LLM-as-a-Judge](/docs/evaluation/evaluation-methods/llm-as-a-judge), [code evaluators](/docs/evaluation/evaluation-methods/code-evaluators), [Jev](/docs/evaluation/evaluation-methods/jev-as-a-judge)) receive **expected output** only when you select them on a [prompt experiment](/docs/evaluation/experiments/experiments-via-ui).

They do not get expected output when a [rule](/docs/evaluation/core-concepts#evaluators-and-rules) scores incoming observations — including observations created by a [webhook](/docs/evaluation/experiments/experiments-via-sdk#configure-webhook) or the [SDK experiment runner](/docs/evaluation/experiments/experiments-via-sdk).

That is why a similarity judge often returns `0` on webhook runs: `{{expected_output}}` (or `{{ground_truth}}`) is empty, so the judge follows an instruction such as "if expected output is missing, return 0".

## What to do instead

| How the experiment runs                                                              | How to attach scores that need expected output                                                                                         |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| [Remote webhook](/docs/evaluation/experiments/experiments-via-sdk#configure-webhook) | Score in the webhook after you fetch the dataset, or call the SDK runner from the webhook. The trigger dialog has no evaluator picker. |
| [SDK experiment runner](/docs/evaluation/experiments/experiments-via-sdk#evaluators) | Pass `evaluators` / `run_evaluators`. Those functions receive `expected_output` / `expectedOutput`.                                    |
| [Prompt experiment](/docs/evaluation/experiments/experiments-via-ui)                 | Select the evaluator on the run and map **Expected Output**.                                                                           |
| Observation-level [rule](/docs/evaluation/get-started/online)                        | Use only for **reference-free** checks. Do not map expected output.                                                                    |

`{{ground_truth}}` is not a reserved parameter. You name prompt variables yourself. Mapping a variable to **Expected Output** is what supplies the dataset label, and that mapping is empty on the rule path.

See [Evaluate externally run experiments](/docs/evaluation/experiments/evaluate-external-experiments) for the full decision table, why a rule cannot follow the dataset-item link, and how to test what the judge received.

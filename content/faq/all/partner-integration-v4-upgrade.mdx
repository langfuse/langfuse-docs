# Vapi and the Langfuse v4 upgrade

Vapi sends data to Langfuse through the [Vapi integration](/integrations/no-code/vapi), which the Vapi team operates. The integration now sends data to the Langfuse [OpenTelemetry endpoint](/integrations/native/opentelemetry) on the [Langfuse v4](/docs/v4) data model, so Vapi projects use the v4 experience with real-time data.

You don't need to change anything in Vapi. Your saved Langfuse credentials keep working.

## What you still need to migrate [#what-to-migrate]

Some project settings and your own code may still use the old data model. Open the **Migration status** page of your Langfuse Cloud region to see what is left for each project, for example [cloud.langfuse.com/v4-migration](https://cloud.langfuse.com/v4-migration) for EU. Other regions use the same path on [their own host](/security/data-regions).

| Item                                                            | What to do                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trace-level or dataset LLM-as-a-Judge evaluators                | [Upgrade to observation-level evaluators](/faq/all/llm-as-a-judge-migration). Since Vapi already sends v4 data, skip the SDK upgrade step.                                                                                                                       |
| PostHog, Mixpanel, or blob storage exports on the legacy source | Switch to enriched observations: [PostHog](/integrations/analytics/posthog#migrate-export-source), [Mixpanel](/integrations/analytics/mixpanel#migrate-export-source), [blob storage](/docs/api-and-data-platform/features/export-to-blob-storage#upgrade-path). |
| Your own code calling deprecated API endpoints                  | [Move to the v4 endpoints](/faq/all/deprecated-api-migration) or upgrade the Langfuse SDK.                                                                                                                                                                       |

<Callout type="warning">
  Trace-level evaluators stop producing results at the Langfuse Cloud v4
  cutover on <V4CutoverDate />. Legacy exports switch to enriched observations
  automatically at the cutover, which changes the event names your downstream
  dashboards receive. If you received an email from us about your Vapi project,
  follow the deadline given there.
</Callout>

An upgraded evaluator scores each matching observation instead of each trace. To keep one score per Vapi call, filter the evaluator on the root observation; the [evaluator upgrade guide](/faq/all/llm-as-a-judge-migration) explains this.

For the complete checklist, see [prepare your project for the v4 upgrade](/faq/all/upgrade-to-langfuse-v4).

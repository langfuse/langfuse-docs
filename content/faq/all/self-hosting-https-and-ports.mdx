# How do I serve self-hosted Langfuse over HTTPS or on a different port?

## HTTPS

Langfuse does not handle TLS itself. Terminate HTTPS at a load balancer or reverse proxy (for example AWS ALB, nginx, Caddy, or Traefik) and forward plain HTTP to the `langfuse-web` container on port `3000`. See [Encryption in transit](/self-hosting/configuration/encryption#https).

Set `NEXTAUTH_URL` to the public URL users open in the browser, for example `https://langfuse.example.com`. Langfuse uses it for sign-in callbacks and for links in the UI and in emails, so a wrong value breaks sign-in. Set the same value on the web and worker containers.

## Different port

In Docker Compose, change the host side (left value) of the port mapping, for example `3001:3000` for the UI, and update `NEXTAUTH_URL` to match. If you move the MinIO port (`9090:9000`), also update `LANGFUSE_S3_MEDIA_UPLOAD_ENDPOINT`. See [Changing the exposed ports](/self-hosting/deployment/docker-compose#ports).

## High availability

The web and worker containers are stateless and can run as multiple replicas behind a load balancer. Docker Compose runs a single instance without high availability; use [Kubernetes (Helm)](/self-hosting/deployment/kubernetes-helm) or a cloud deployment for that. See [Using a load balancer](/faq/all/self-host-with-load-balancer).

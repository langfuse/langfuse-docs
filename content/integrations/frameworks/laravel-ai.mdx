# Integrating Langfuse with Laravel AI

This guide shows how to integrate [Langfuse](/) with the [Laravel AI SDK](https://laravel.com/docs/ai-sdk) using OpenTelemetry.

**Laravel AI**: First-party Laravel SDK for building agents, tools, and embeddings.

**Langfuse**: Open source AI engineering platform for observability, evals and prompt management.

<Callout type="info">
  This integration uses the community package
  [`cristea-iulian/laravel-ai-otel`](https://github.com/cristea-iulian/laravel-ai-otel).
  It is not maintained by Langfuse. A ready-made demo app is available at
  [laravel-ai-otel-demo](https://github.com/cristea-iulian/laravel-ai-otel-demo).
</Callout>

The package turns Laravel AI SDK events into OpenTelemetry spans that follow the [GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/). Langfuse maps those spans onto its data model with no Langfuse-specific code: `invoke_agent` becomes an agent observation, `chat` a generation (model, tokens, finish reasons), and `execute_tool` a tool, with sub-agents nested under the tool that delegated to them.

```text
invoke_agent SupportAgent      AGENT       (root)
├── chat {model}               GENERATION
├── LookupOrder                TOOL
├── ResearchAgent              TOOL
│   └── invoke_agent Research… AGENT
│       └── chat {model}       GENERATION
├── chat {model}               GENERATION
├── EstimateShipping           TOOL
└── chat {model}               GENERATION
```

## Step 1: Install the instrumentation

Install the Laravel AI SDK (if you do not already have it), the community OpenTelemetry package, and the OTLP exporter:

```bash
composer require laravel/ai cristea-iulian/laravel-ai-otel
composer require open-telemetry/sdk open-telemetry/exporter-otlp
```

The package registers itself. If you already run [`open-telemetry/opentelemetry-auto-laravel`](https://packagist.org/packages/open-telemetry/opentelemetry-auto-laravel) (or any SDK that registers a global `TracerProvider`), you can skip the second `composer require` — agent spans are recorded through that provider and nest under the HTTP request or queue job that triggered them.

Requirements: PHP 8.3+, Laravel 12 or 13, and `laravel/ai` 0.11.x.

## Step 2: Configure Langfuse [#step-2-configure-langfuse]

Sign up for [Langfuse Cloud](https://langfuse.com/cloud) or [self-host Langfuse](https://langfuse.com/self-hosting). Then point the OpenTelemetry exporter at the Langfuse OTLP endpoint.

Authentication uses HTTP Basic Auth: build the credential by base64-encoding your `public_key:secret_key` pair, then pass it (along with the ingestion-version header) via the standard OpenTelemetry environment variables:

```bash
# Build the Basic Auth string from your Langfuse API keys
export AUTH_STRING=$(echo -n "pk-lf-...:sk-lf-..." | base64 -w0) # Linux
# macOS (BSD base64 has no -w0): export AUTH_STRING=$(echo -n "pk-lf-...:sk-lf-..." | base64)

export OTEL_EXPORTER_OTLP_ENDPOINT="https://cloud.langfuse.com/api/public/otel" # 🇪🇺 EU data region
# Other regions: 🇺🇸 US https://us.cloud.langfuse.com/api/public/otel, 🇯🇵 Japan https://jp.cloud.langfuse.com/api/public/otel, ⚕️ HIPAA https://hipaa.cloud.langfuse.com/api/public/otel
# Self-hosted (>= v3.22.0): http://localhost:3000/api/public/otel
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Basic ${AUTH_STRING},x-langfuse-ingestion-version=4"
export OTEL_EXPORTER_OTLP_PROTOCOL=http/json
export OTEL_SERVICE_NAME=my-laravel-app
```

<Callout type="warning">
  Set `OTEL_EXPORTER_OTLP_PROTOCOL=http/json`. Langfuse accepts the spans under
  the default `http/protobuf` as well, but it currently answers with a JSON
  ingestion-job body instead of an `ExportTraceServiceResponse`. The
  OpenTelemetry PHP exporter cannot parse that response and logs an export
  failure for every batch, even though the spans are stored. `http/json` avoids
  the noise.
</Callout>

<Callout type="info">
  See the [OpenTelemetry setup](/integrations/native/opentelemetry) for Basic
  Auth and the [real-time ingestion
  section](/integrations/native/opentelemetry#real-time-ingestion) for the
  `x-langfuse-ingestion-version` header.
</Callout>

Put the same variables in your Laravel `.env` for local and deployed environments.

## Step 3: Run a test agent

Prompt any Laravel AI agent. The package listens to the SDK's events, so no code changes are required:

```php
use function Laravel\Ai\{agent};

$response = agent(
    instructions: 'You are a helpful assistant.',
)->prompt('What is Langfuse?');

return (string) $response;
```

A dedicated agent class works the same way. Tools, sub-agents, provider failover, and embeddings are recorded automatically.

After the request finishes, open [Langfuse Cloud](https://langfuse.com/cloud) (or your self-hosted UI) and confirm the agent run appears as a nested trace.

## Capture prompts and completions

By default the package records metadata only (models, providers, token counts, durations, tool names, finish reasons, ids). Prompts, completions, system instructions, and tool arguments or results are **not** sent unless you opt in, following the GenAI conventions:

```dotenv
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
AI_OTEL_CAPTURE_MAX_LENGTH=8192
```

<Callout type="info">
  Content capture is off by default. Enable it only when you need prompt and
  completion text in Langfuse, and use the package's redaction hook if those
  strings can contain personal data. See
  [Privacy and content capture](https://github.com/cristea-iulian/laravel-ai-otel#privacy-and-content-capture)
  in the package README.
</Callout>

## What is recorded

| Span                   | Langfuse type | Source                                                                        |
| ---------------------- | ------------- | ----------------------------------------------------------------------------- |
| `invoke_agent {Agent}` | Agent         | Agent prompt / stream / failure                                               |
| `chat {model}`         | Generation    | Each agent step, including usage (input, output, cache, and reasoning tokens) |
| `execute_tool {tool}`  | Tool          | Tool invocations; a sub-agent nests under the tool that called it             |
| `embeddings {model}`   | Embedding     | Embedding requests                                                            |

Failed steps, tools, and runs set span status `ERROR` and record the exception. Provider failover is a span event on the parent `invoke_agent` span.

To attach [users](/docs/observability/features/users) and [sessions](/docs/observability/features/sessions), set `langfuse.user.id` and `langfuse.session.id` (or `user.id` / `session.id`) on the spans. See [Propagating trace attributes](/integrations/native/opentelemetry#propagating-attributes).

## Troubleshooting

**No traces:**

- Confirm an agent or embedding call actually ran, then wait for the request or queue job to finish so the batch exporter can flush.
- Check `OTEL_EXPORTER_OTLP_ENDPOINT` and the Basic Auth header against your Langfuse project keys and region.
- If you did not install `open-telemetry/sdk` and `open-telemetry/exporter-otlp`, and you have no other TracerProvider, the package throws `MissingOpenTelemetrySdkException` and names the packages to install.

**Export failures in the logs, but traces appear in Langfuse:**

- Set `OTEL_EXPORTER_OTLP_PROTOCOL=http/json`. This is the PHP exporter response-parsing issue described in Step 2.

**Missing prompts, completions, or tool payloads:**

- Content capture is opt-in. Set `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true`.

**Queued agent runs are separate traces:**

- Install [`open-telemetry/opentelemetry-auto-laravel`](https://packagist.org/packages/open-telemetry/opentelemetry-auto-laravel) so queue jobs inherit the request's trace context. Without it, use `laravel.ai.invocation.id` (also on `$response->invocationId`) to correlate.

# Trace OpenAI Agents SDK tool calls with Langfuse

Langfuse shows every tool call, handoff and model call of an OpenAI Agents SDK run in one trace, with the arguments, the results and the token use. Two lines in Python send the traces, `OpenAIAgentsInstrumentor().instrument()` and `get_client()`, and your agent code stays the same.

> **What is the OpenAI Agents SDK?** The [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) is OpenAI's open source Python framework for building agents from tools, handoffs and guardrails. It runs agents with `Runner.run` and records each run as a trace with spans.

> **What is Langfuse?** [Langfuse](/) is an open source LLM engineering platform for tracing, evaluating and debugging AI agents. Use [Langfuse Cloud](/cloud) or [self-host](/self-hosting) it.

> **How do they work together?** The OpenAI Agents SDK lists Langfuse among its [external tracing processors](https://openai.github.io/openai-agents-python/tracing/). The OpenInference instrumentor turns each Agents SDK span into an OpenTelemetry span, and the Langfuse client exports it to Langfuse.

<Callout type="info">
  Requires Python 3.11 or later (Langfuse Python SDK 5). The code on this page ran with `langfuse` 5.2.0, `openai-agents` 0.26.0 and `openinference-instrumentation-openai-agents` 2.8.7, as of November 2026.

</Callout>

## Send traces to Langfuse [#setup]

Install the Agents SDK, the Langfuse SDK and the OpenInference instrumentor, a third-party package maintained by Arize:

```bash
pip install langfuse openai-agents openinference-instrumentation-openai-agents
```

Add your [Langfuse API keys](/docs/observability/sdk/overview#client-setup) and your OpenAI key to your shell environment:

```bash
export LANGFUSE_SECRET_KEY="sk-lf-..."
export LANGFUSE_PUBLIC_KEY="pk-lf-..."
export LANGFUSE_BASE_URL="https://cloud.langfuse.com" # 🇪🇺 EU region
# Other Langfuse data regions include 🇺🇸 US: https://us.cloud.langfuse.com, 🇯🇵 Japan: https://jp.cloud.langfuse.com and ⚕️ HIPAA: https://hipaa.cloud.langfuse.com
export OPENAI_API_KEY="sk-proj-..."
```

Call the instrumentor before the first run. `auth_check()` stops the script with `UnauthorizedError` if Langfuse rejects the keys or the host.

```python filename="agent.py"
import asyncio

from agents import Agent, Runner, function_tool
from langfuse import get_client, propagate_attributes
from openinference.instrumentation.openai_agents import OpenAIAgentsInstrumentor

# Send every Agents SDK trace to Langfuse. Call this before the first run.
OpenAIAgentsInstrumentor().instrument()

langfuse = get_client()
assert langfuse.auth_check(), "Langfuse rejected the keys or the host"

@function_tool
def get_weather(city: str) -> str:
    """Return the weather for a city."""
    return f"The weather in {city} is sunny."

agent = Agent(
    name="Weather agent",
    instructions="Answer weather questions with the get_weather tool.",
    tools=[get_weather],
    model="gpt-4.1-mini",
)

async def main():
    with propagate_attributes(trace_name="weather-agent", user_id="user-123", session_id="session-abc"):
        result = await Runner.run(agent, "What is the weather in Tokyo?")
    print(result.final_output)

asyncio.run(main())
langfuse.flush()  # a short script exits before the background export runs
```

## Tool calls, handoffs and model calls in one trace [#trace]

Each `Runner.run` becomes one trace. With instrumentor 2.8.7 the script above produces these spans:

- `Agent workflow`: the run, with the user input and the final output
- `Weather agent`: the agent, with its tools and handoffs
- `generation`: each model call, with the prompt, the response and the token use
- `get_weather`: the tool call, with its arguments and result
- `turn`: each step of the agent loop

Span names depend on the instrumentor version. A [handoff](https://openai.github.io/openai-agents-python/handoffs/) to another agent appears as a span of its own, followed by the spans of the agent that took over. Cost appears when Langfuse has a [price for the model](/docs/observability/features/token-and-cost-tracking).

## Users, sessions and tags [#users-sessions]

`propagate_attributes` sets the trace name, the [user ID](/docs/observability/features/users), the [session ID](/docs/observability/features/sessions) and tags on every span inside its block, so you can filter traces by user and follow a conversation across runs. Wrap one `Runner.run` call, or several to group them in one session.

## Export to OpenAI and Langfuse [#openai-dashboard]

The Agents SDK exports traces to the OpenAI dashboard by default. In instrumentor 2.8.7, `instrument()` replaces the SDK's default processors, so traces go to Langfuse only. To keep both, pass `exclusive_processor=False`:

```python
OpenAIAgentsInstrumentor().instrument(exclusive_processor=False)
```

## Link a Langfuse prompt [#prompts]

If you manage the agent's instructions in [Langfuse Prompt Management](/docs/prompt-management/overview), pass the prompt to `propagate_attributes(prompt=langfuse.get_prompt("weather-agent"))`. Langfuse links it to the model calls of the run, so you can compare prompt versions by latency, cost and scores. See [Link prompts to traces](/docs/prompt-management/features/link-to-traces).

## Troubleshooting [#troubleshooting]

If no trace appears:

- Check that `langfuse.auth_check()` passes and that the keys belong to the region in `LANGFUSE_BASE_URL`.
- Call `OpenAIAgentsInstrumentor().instrument()` before the first `Runner.run`.
- Call `langfuse.flush()` before a short script exits.
- Set `LANGFUSE_DEBUG="True"` to log what the SDK exports.

See [Missing traces](/faq/all/missing-traces) for more causes.

## FAQ [#faq]

**How do I trace OpenAI Agents SDK tool calls?** Call `OpenAIAgentsInstrumentor().instrument()` and `get_client()` before the first run. Every function tool call appears as a span in the trace, with its arguments and result.

**Does Langfuse show handoffs between agents?** Yes. Handoffs and the calls of each agent are captured in the same trace.

**Do the traces still go to the OpenAI dashboard?** Not by default with instrumentor 2.8.7. `exclusive_processor=False` keeps both.

**Can I self-host Langfuse for this?** Yes. Set `LANGFUSE_BASE_URL` to your instance.

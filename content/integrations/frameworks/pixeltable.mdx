# Trace Pixeltable with Langfuse

[Pixeltable](https://docs.pixeltable.com) runs model calls inside computed columns and user-defined functions. Langfuse records each Pixeltable operation as a trace: the rows, the UDF calls, and a generation for every LLM request, with the prompt, completion, model, token usage, and latency.

Thanks to the team at Pixeltable for this guide. Pixeltable's own write-up is on the [Pixeltable Langfuse page](https://docs.pixeltable.com/integrations/langfuse).

> **What is Pixeltable?** [Pixeltable](https://github.com/pixeltable/pixeltable) is declarative data infrastructure for multimodal AI applications. Images, video, audio, documents, and model calls live in tables, and a transform is a computed column that runs when you insert or update a row. See the [Pixeltable docs](https://docs.pixeltable.com).

> **What is Langfuse?** [Langfuse](https://langfuse.com) is an open-source LLM engineering platform that helps teams trace, debug, and evaluate LLM applications. Use [Langfuse Cloud](/cloud) (hosted by Langfuse, free tier, no infrastructure to run) or [self-host](/self-hosting) it.

With `span_level="debug"`, one table operation looks like this:

```
pixeltable.insert
└─ pixeltable.store.insert_rows
   ├─ pixeltable.row
   ├─ pixeltable.udf.chat_completions
   │  └─ ChatCompletion          (generation: model, tokens, cost)
   └─ pixeltable.sa.insert_rows
```

Pixeltable's spans record which operation, row, column, and UDF ran. An LLM instrumentor adds the generation underneath, including token usage and cost. Pixeltable sets the active OpenTelemetry context for every UDF call, including work on its thread pools, so that generation nests under the UDF span (`pixeltable.udf.chat_completions` for a chat-completions column).

| You want                                                                                       | Use                                       |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Pixeltable operations, rows, UDF calls, and LLM generations, with no Langfuse SDK in your code | [OpenTelemetry export](#otel-export)      |
| Those spans, plus `@observe`, trace names, tags, metadata, and one trace around a batch        | [Langfuse SDK](#langfuse-sdk)             |
| Only the LLM generations                                                                       | [LLM generations only](#generations-only) |

## Install dependencies

```bash
pip install 'pixeltable[otel]' openai langfuse openinference-instrumentation-openai
```

The `otel` extra installs Pixeltable's OpenTelemetry bridge (`opentelemetry-instrumentation-pixeltable`) together with the OpenTelemetry SDK and OTLP exporter. `openai` is the client that `chat_completions()` calls; neither Pixeltable nor the instrumentor installs it. `openinference-instrumentation-openai` adds generation spans for OpenAI calls. Other OpenInference instrumentors that attach to the global tracer provider work the same way.

## Configure credentials

Create a project in [Langfuse Cloud](https://cloud.langfuse.com) or on a [self-hosted](/self-hosting) instance, then copy the public and secret keys from the project settings. Use the base URL of the region where that project lives. A project's keys authenticate only against that region's host.

```python
import os

# Get keys for your project from the project settings page: https://cloud.langfuse.com
os.environ.setdefault("LANGFUSE_PUBLIC_KEY", "pk-lf-...");
os.environ.setdefault("LANGFUSE_SECRET_KEY", "sk-lf-...");
os.environ.setdefault("LANGFUSE_BASE_URL", "https://cloud.langfuse.com");  # 🇪🇺 EU region
# Other Langfuse data regions include 🇺🇸 US: https://us.cloud.langfuse.com, 🇯🇵 Japan: https://jp.cloud.langfuse.com and ⚕️ HIPAA: https://hipaa.cloud.langfuse.com

# Provider key for the model your computed columns call
os.environ.setdefault("OPENAI_API_KEY", "sk-proj-...");
```

For a self-hosted Langfuse instance, set `LANGFUSE_BASE_URL` to that host. The examples below append `/api/public/otel`.

## Export OpenTelemetry spans [#otel-export]

Pixeltable emits OpenTelemetry spans for its own work once you turn the bridge on. Langfuse accepts OTLP over HTTP at `LANGFUSE_BASE_URL/api/public/otel`, authenticated with HTTP Basic auth (`public_key:secret_key`). Call `pxt_otel.init()` once per process, before the first Pixeltable operation.

```python
import base64
import os

import opentelemetry.instrumentation.pixeltable as pxt_otel
from openinference.instrumentation.openai import OpenAIInstrumentor
from opentelemetry import trace

base_url = os.environ.get("LANGFUSE_BASE_URL", "https://cloud.langfuse.com").rstrip("/")
token = base64.b64encode(
    f"{os.environ['LANGFUSE_PUBLIC_KEY']}:{os.environ['LANGFUSE_SECRET_KEY']}".encode()
).decode()

# Once per process, before the first Pixeltable operation.
pxt_otel.init(
    endpoint=f"{base_url}/api/public/otel",  # the exporter appends /v1/traces
    headers=f"Authorization=Basic {token},x-langfuse-ingestion-version=4",
    service_name="pixeltable-app",
    span_level="debug",  # adds row, UDF, and file spans; "info" keeps operation, catalog, store, and SQL spans
    metrics=False,  # Langfuse ingests traces
)
OpenAIInstrumentor().instrument()

import pixeltable as pxt
from pixeltable.functions import openai

t = pxt.create_table("articles", {"id": pxt.Int, "body": pxt.String}, if_exists="replace")
t.add_computed_column(
    summary=openai.chat_completions(
        messages=[{"role": "user", "content": "Summarize in one sentence: " + t.body}],
        model="gpt-4o-mini",
    ).choices[0].message.content
)
t.insert(
    [
        {
            "id": 1,
            "body": "Pixeltable is declarative data infrastructure for multimodal AI apps.",
        }
    ]
)

trace.get_tracer_provider().force_flush()  # short-lived scripts: send spans before exit
```

<Callout type="info">
  The `x-langfuse-ingestion-version=4` header makes directly exported spans show
  up in real time. Without it, OpenTelemetry data can take up to 10 minutes to
  appear. See [OpenTelemetry ingestion](/integrations/native/opentelemetry#real-time-ingestion).
</Callout>

You can set `OTEL_EXPORTER_OTLP_ENDPOINT` and `OTEL_EXPORTER_OTLP_HEADERS` instead of passing `endpoint` and `headers`. Pixeltable also reads the endpoint from the `[otel]` section of `~/.pixeltable/config.toml`. Keep the authorization header in the environment, because it contains your secret key. Details are in Pixeltable's [observability guide](https://docs.pixeltable.com/platform/observability).

To trace a served app, run `pxt service run` or `pxt service update` with `--otel`. It calls `pxt_otel.init()` before it loads the app file, so configure the export in the environment:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="$LANGFUSE_BASE_URL/api/public/otel"
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Basic $(printf '%s' "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" | base64 | tr -d '\n'),x-langfuse-ingestion-version=4"
export OTEL_METRICS=false
export OTEL_SPAN_LEVEL=debug
```

The app file must not call `pxt_otel.init()`. If the database entry in `pixeltable.toml` sets `db_exporter_otlp_endpoint`, that value wins over `OTEL_EXPORTER_OTLP_ENDPOINT`.

<Callout type="warning">
  Instrument each model provider once. The Anthropic Python SDK emits its own
  OpenTelemetry spans for `messages.create`, and Langfuse records those as
  generations, so leave `openinference-instrumentation-anthropic` off when
  those spans are already present. Enabling both stores a second generation
  and counts the cost twice. The same applies to `langfuse.openai` together
  with `OpenAIInstrumentor`.
</Callout>

## Add Langfuse SDK features [#langfuse-sdk]

Use the Langfuse SDK when you also want `@observe`, trace names, tags, metadata, user or session ids, or one trace around a batch.

Create the Langfuse client first and pass `should_export_span`. From SDK v4 onward, Langfuse exports Langfuse spans, `gen_ai.*` spans, and known LLM-instrumentor spans by default, which drops Pixeltable's spans. Passing `should_export_span` replaces that filter, so compose it with `is_default_export_span` and allow the `pixeltable` instrumentation scope. See [filtering by instrumentation scope](/docs/observability/sdk/advanced-features#filtering-by-instrumentation-scope).

Attach Pixeltable with `PixeltableInstrumentor().instrument()`. That uses the global provider the Langfuse client already installed. `pxt_otel.init()` builds its own provider, so use it only in the [OpenTelemetry export](#otel-export) approach above.

```python
from langfuse import Langfuse, propagate_attributes
from langfuse.span_filter import is_default_export_span


def export_span(span) -> bool:
    scope = span.instrumentation_scope
    return is_default_export_span(span) or (
        scope is not None and scope.name == "pixeltable"
    )


langfuse = Langfuse(should_export_span=export_span)

if langfuse.auth_check():
    print("Langfuse client is authenticated and ready!")
else:
    print("Authentication failed. Please check your credentials and host.")

from openinference.instrumentation.openai import OpenAIInstrumentor
from opentelemetry.instrumentation.pixeltable import PixeltableInstrumentor

PixeltableInstrumentor().instrument(span_level="debug")
OpenAIInstrumentor().instrument()

import pixeltable as pxt
```

### Trace custom UDFs [#custom-udfs]

Put `@pxt.udf` outermost and `@observe` under it. Pixeltable does not allow a UDF defined in the `__main__` module of a script. Define UDFs in a module and import them.

```python title="my_udfs.py"
import openai
import pixeltable as pxt
from langfuse import observe, propagate_attributes

client = openai.AsyncOpenAI()


@pxt.udf
@observe(name="word_count")
def word_count(text: str) -> int:
    return len(text.split())


@pxt.udf
@observe(name="headline")
async def headline(text: str, row_id: int) -> str:
    # Attach this row id to the @observe span and to the LLM call inside it.
    # Propagated metadata values must be 200 characters or fewer.
    with propagate_attributes(metadata={"row_id": str(row_id)}):
        response = await client.chat.completions.create(
            model="gpt-4o-mini",
            max_tokens=20,
            messages=[
                {
                    "role": "user",
                    "content": f"Write a 5-word headline for: {text}",
                }
            ],
        )
    return response.choices[0].message.content
```

On the `articles` table from the example above:

```python
import pixeltable as pxt
from my_udfs import headline, word_count

t = pxt.get_table("articles")
t.add_computed_column(words=word_count(t.body))
t.add_computed_column(title=headline(t.body, t.id))
```

The `@observe` span nests under the Pixeltable UDF span, and LLM calls made inside it nest under the `@observe` span. This works for synchronous and asynchronous UDFs. Pixeltable's own spans do not include row ids or cell values. To attach an id, pass the column into a UDF and call `propagate_attributes()` inside it, as `headline()` does. Metadata rules are in [Metadata](/docs/observability/features/metadata).

### Group a batch into one trace [#one-trace-per-batch]

By default, every Pixeltable operation starts its own trace. Wrap the call to group a batch under a name you choose and attach metadata. `propagate_attributes` copies the trace name, tags, and metadata onto each span in the context.

```python
rows = [
    {
        "id": 1,
        "body": "Pixeltable is declarative data infrastructure for multimodal AI apps.",
    },
    {
        "id": 2,
        "body": "Langfuse is an open-source LLM engineering platform for tracing and evals.",
    },
]

with langfuse.start_as_current_observation(name="ingest-docs", as_type="span"):
    with propagate_attributes(
        trace_name="ingest-docs",
        tags=["pixeltable"],
        metadata={"table": "articles"},
    ):
        t.insert(rows)

langfuse.flush()
```

`pixeltable.insert`, its row and UDF spans, the `@observe` spans, and every generation land in that one trace. Each of them carries `table` in its metadata. The same wrapper covers `add_computed_column`, which backfills existing rows.

Open [Traces](https://cloud.langfuse.com/project/~/traces) and filter by the trace name (`ingest-docs`), the `pixeltable` tag, or metadata (`table`).

## LLM generations only [#generations-only]

To record the model calls and skip Pixeltable spans, import `langfuse.openai` before Pixeltable runs. The wrapper patches the `openai` module, including the `AsyncOpenAI` client that `pixeltable.functions.openai` uses, so each computed-column call becomes an OpenAI generation with tokens and cost.

You can also create a Langfuse client and call `OpenAIInstrumentor().instrument()` on its own. Each insert then produces one trace per LLM call. To group a batch under one trace, use the [Langfuse SDK](#langfuse-sdk) approach. Without the Pixeltable bridge, a notebook or any caller with a running event loop runs the query on a worker thread that does not carry the Langfuse context.

## Notes [#notes]

- With the bridge on, every Pixeltable call is traced, including `create_dir`, `create_table`, `drop_dir`, and `collect`. `span_level="info"` drops the per-row, per-UDF, and per-file spans. On an insert, the generation then nests under `pixeltable.store.insert_rows`.
- Computed-column results are stored. `collect()` produces a Pixeltable span and does not call the model again. LLM calls run on `insert`, on `update`, and when `add_computed_column` backfills existing rows.
- Flush before a short-lived script exits: `trace.get_tracer_provider().force_flush()` for OpenTelemetry export, or `langfuse.flush()` for the SDK.
- Turn tracing on before the first Pixeltable operation.
- Prompts and completions are sent to Langfuse. Pixeltable's log export (`logs=True`) is off by default. Leave it off unless the logs are redacted.

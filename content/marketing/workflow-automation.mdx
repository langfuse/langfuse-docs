# Build reliable automation agents

Workflow automation includes dozens of steps across systems and frameworks. Trace the full execution, track cost at every step, and continuously include human expertise to improve your system.

<UseCaseCtas />

## Debug agent executions [#debug]

Trace every step, tool call, and input and output your agent produces. Find failure modes and bottlenecks across executions, then prioritize issues by how often they happen so you fix what actually matters.

A typical automation run spans APIs, tools, and models. [Langfuse traces](/docs/observability/overview) stitch that path into one timeline you can inspect, share, and filter. Use [agent graphs](/docs/observability/features/agent-graphs) to see the workflow as it ran, and [sessions](/docs/observability/features/sessions) when a job spans multiple traces.

[Get started with tracing](/docs/observability/get-started) in minutes, then follow [what a good trace looks like](/docs/observability/best-practices) so debugging, evaluation, and cost tracking stay useful as the system grows.

## See cost at every step [#cost]

Get a detailed view of cost for an execution as a whole and a granular view of each sub-step. Swap models and inspect quality so you can manage the cost of the system without guessing.

Langfuse [tracks tokens and cost](/docs/observability/features/token-and-cost-tracking) for popular models out of the box, including nested tool and LLM calls. Break spend down by model, user, or workflow, then compare quality after a model swap with [experiments](/docs/evaluation/experiments/datasets).

## Improve with human expertise [#human-expertise]

Let engineers and domain experts annotate data in Langfuse and mark when the system went wrong. Log corrections from human-in-the-loop setups to build ground-truth data at scale.

Use [annotation queues](/docs/evaluation/evaluation-methods/annotation-queues) to review failing runs, [scores in the UI](/docs/evaluation/evaluation-methods/scores-via-ui) to label what good looks like, and [corrections](/docs/observability/features/corrections) to capture the output the agent should have produced. Those labels become [datasets](/docs/evaluation/experiments/datasets) you can rerun as the workflow changes.

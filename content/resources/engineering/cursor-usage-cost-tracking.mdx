# Track Cursor agent usage and cost with Langfuse

Cursor's billing tells you what your team was charged. It doesn't tell you which agent sessions used the tokens, which tool calls looped, or which developer's workflow costs three times the average. The [Langfuse Cursor plugin](/integrations/developer-tools/cursor) records every Cursor agent turn with its token usage and cost, so you can answer those questions per developer, per session, and per model.

<SignupCTA className="my-6" />

**TL;DR:** Install the Langfuse Observability plugin from the Cursor Marketplace, or with npm for the CLI and Cloud Agents, and add your Langfuse project keys. Each prompt becomes one trace with its model generations, tool calls, subagents, and token usage. Langfuse prices the tokens with its model definitions, and turns from one conversation are grouped into a session. Cursor isn't supported by the Langfuse AI Gateway, so the plugin is the way to track it.

## What the plugin records [#what-it-records]

The plugin reads [Cursor hooks](https://cursor.com/docs/hooks) and Cursor's session transcript, then sends one trace per turn:

- **Agent turns** appear as one `Cursor Turn` trace per prompt, from your message to the final answer. Aborted turns are marked `WARNING` and failed turns `ERROR`.
- **Model generations** are recorded as one `LLM` observation per assistant message, with the conversation history as input and the model parameters.
- **Token usage and cost** are reported once per turn: Cursor reports input, output, cache-read, and cache-write tokens on the last `LLM` observation, and the trace total is the turn's cost.
- **Tool calls** include every tool Cursor runs (shell, file reads and writes, search, MCP tools) with input, output, duration, and diffs for file edits.
- **Subagents** are nested under the tool call that spawned them.
- **Skills** are tagged as `skill:<name>` whenever the agent reads a skill or runs one of its scripts.
- **Sessions and users** group all turns of one conversation into a session, with the signed-in Cursor account as the user.

## Setting it up for a team [#team-setup]

For individual developers, the Cursor Marketplace install is the fastest path: install **Langfuse Observability**, start a chat, and paste the project keys into the `~/.cursor/langfuse.json` file the plugin creates.

For a team, two choices make the data useful:

1. **Use one Langfuse project for the whole team.** Cost comparisons only work when all developers' turns land in the same project.
2. **Register the hooks per repository** with `langfuse-cursor-hook setup --project .` when everyone working in a repository should be traced, including Cloud Agents and the Cursor CLI.

The [Cursor integration page](/integrations/developer-tools/cursor) has the full configuration reference, including environment variables and the npm install.

<Callout type="info">
  Cost is computed from Cursor's reported tokens and Langfuse's [model
  prices](/docs/observability/features/token-and-cost-tracking). A model
  without a price definition shows tokens but no cost, so add a custom model
  price for any model Cursor uses that Langfuse doesn't price yet. The figure is
  an API-equivalent estimate, not your Cursor invoice.
</Callout>

## Questions the data answers [#questions]

1. **Which developers and sessions use the most tokens?** Group traces by user, then open the most expensive sessions to see what the agent did.
2. **Which tools fail or loop?** Filter tool observations by level to find failed, timed-out, and denied calls, and see which tasks repeat them.
3. **How much do subagents cost?** Subagent generations are nested under their parent tool call, so you can see how much of a turn's cost came from delegated work.
4. **Which skills are in use?** The `skill:<name>` tags show which team skills the agent reads and how sessions that use them compare.

For dashboards, see [custom dashboards](/docs/metrics/features/custom-dashboards). To compare Cursor with other agents on one dashboard, see [coding agent cost tracking](/resources/engineering/coding-agent-cost-tracking).

## Limits of hook-based tracking [#limits]

- **Developers can turn it off.** The plugin runs on each machine, so a developer can remove it. Treat it as telemetry, not enforcement.
- **Node.js 22 must be on the PATH** of the process that launches Cursor, and self-hosted Langfuse must run v4.
- **Usage is reported per turn.** Per-message token counts are not available, only the turn total.

## FAQ

<FaqDetails>

<Details id="does-the-gateway-support-cursor">
<Summary>Can I route Cursor through the Langfuse AI Gateway?</Summary>

No. Cursor isn't one of the coding agents the gateway supports. Use the Langfuse Cursor plugin, which traces Cursor from hooks without changing how Cursor calls its models.

</Details>

<Details id="does-it-capture-code">
<Summary>Does the plugin send my code to Langfuse?</Summary>

The plugin sends the turn's conversation, tool inputs and outputs, and file edit diffs, so code that appears in the session is included. Use a Langfuse project with the access controls and [data retention](/docs/administration/data-retention) your team needs, or self-host Langfuse to keep the data in your infrastructure.

</Details>

<Details id="cloud-agents">
<Summary>Does it work with Cursor Cloud Agents and the CLI?</Summary>

Yes. Install with npm and register the hooks in the repository's `.cursor/hooks.json`, which Cloud Agents and the Cursor CLI read. Credentials can come from environment variables in those environments.

</Details>

</FaqDetails>

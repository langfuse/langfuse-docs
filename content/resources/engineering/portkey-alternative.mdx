# Portkey alternative: Langfuse AI Gateway compared

Portkey is an AI gateway with an open source core and a hosted platform for routing, guardrails, and logs. Since Palo Alto Networks completed its acquisition of Portkey in May 2026, it is part of the Prisma AIRS security platform. Teams reviewing their gateway after that change often ask how the Langfuse AI Gateway compares. The short answer: Portkey covers more providers and routing features, and Langfuse covers access and tracing for the major providers in the same tool as your application observability.

<SignupCTA className="my-6" />

**TL;DR:** Choose **Portkey** when you need many providers, fallbacks, retries, load balancing, conditional routing, or semantic caching. Choose the **[Langfuse AI Gateway](/docs/gateway/overview)** when you use OpenAI, Anthropic, or Amazon Bedrock and want per-person keys, a model allowlist, and every call traced in Langfuse, with an open source self-hosting option. You can also keep Portkey and send its traffic to Langfuse with the [Portkey integration](/integrations/gateways/portkey). Details as of November 2026.

## Side-by-side comparison [#comparison]

Verified against Portkey's public documentation, pricing page, and GitHub repository in November 2026. Check the linked sources before you decide.

| Capability         | Langfuse AI Gateway                                                  | Portkey                                                                                          |
| ------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Providers          | OpenAI, Anthropic, Amazon Bedrock                                    | "1,600+ LLMs" across many providers, per its [repository](https://github.com/Portkey-AI/gateway) |
| API format         | Native OpenAI and Anthropic APIs, no translation                     | OpenAI-compatible unified API                                                                    |
| Routing            | Not available during the beta                                        | Fallbacks, retries, load balancing, conditional routing                                          |
| Caching            | Not available                                                        | Semantic caching on hosted and enterprise plans                                                  |
| Guardrails and PII | On the [roadmap](/docs/gateway/overview#roadmap)                     | Guardrails; PII redaction on hosted and enterprise plans                                         |
| Keys               | User keys and service account keys, expiry, revocation, metadata     | Virtual keys; budgets and rate limits on Enterprise and select plans                             |
| Tracing            | Every call is a Langfuse generation, next to your application traces | Request logs in Portkey, with retention by plan                                                  |
| Self-hosting       | Open source, deploys with self-hosted Langfuse                       | MIT-licensed open source gateway; the full platform on enterprise plans                          |
| Ownership          | Langfuse                                                             | Palo Alto Networks, part of Prisma AIRS since May 2026                                           |

Portkey's published plans, as of November 2026: a free Developer plan with 10,000 logs per month and 3 days of log retention, a Production plan at $49 per month with 100,000 logs and 30 days of retention, and custom Enterprise pricing. Gateway calls in Langfuse count as [billable units](/docs/administration/billable-units) like any other observation, and your provider bills model usage to your own account.

  The Langfuse AI Gateway is in beta. It doesn't retry, fall back, or cache,
  and recording is best-effort. See [known

## Where Portkey fits better [#portkey]

- **Many providers behind one API,** including providers the Langfuse AI Gateway doesn't support.
- **Reliability and routing:** fallbacks, retries, load balancing, and routing on request conditions.
- **Guardrails in the request path,** such as blocking or redacting content before it reaches a model.
- **Caching** to cut cost on repeated requests.

## Where the Langfuse AI Gateway fits better [#langfuse]

- **One tool for gateway and application traces.** Gateway calls are Langfuse generations, so you can evaluate, annotate, and chart them, and nest them in SDK traces with `traceparent`. See [AI gateway vs SDK tracing](/resources/engineering/ai-gateway-vs-sdk-tracing).
- **Coding agents.** Native APIs and automatic sessions for Claude Code and Codex. See [coding agent cost tracking](/resources/engineering/coding-agent-cost-tracking).
- **People-based keys.** User keys record their owner and stop working when that person leaves. See [gateway API keys](/resources/engineering/ai-gateway-api-keys).
- **Self-hosting with the rest of your observability stack.** See [self-host an open source AI gateway](/resources/engineering/self-hosted-ai-gateway).

## Use Portkey with Langfuse [#together]

If Portkey stays your routing layer, you can still trace its traffic in Langfuse: call Portkey through the OpenAI SDK and trace that client with Langfuse, as shown in the [Portkey integration](/integrations/gateways/portkey). Don't also route the same calls through the Langfuse AI Gateway, or each call is recorded twice.

For a wider overview of gateways, see [LLM gateways](/resources/engineering/llm-gateway). For LiteLLM, see [Langfuse AI Gateway vs LiteLLM Proxy](/resources/engineering/ai-gateway-vs-litellm).

## FAQ

<FaqDetails>

<Details id="portkey-acquisition">
<Summary>Who owns Portkey?</Summary>

Palo Alto Networks completed its acquisition of Portkey on May 29, 2026, and Portkey is now part of its Prisma AIRS AI security platform. Check Portkey's site for current plans and terms.

</Details>

<Details id="portkey-open-source">
<Summary>Is Portkey open source?</Summary>

The Portkey gateway is MIT-licensed on GitHub. Features such as semantic caching, PII redaction, and budgets are part of the hosted and enterprise platform, according to its documentation as of November 2026.

</Details>

<Details id="migrate-from-portkey">
<Summary>How do I move from Portkey to the Langfuse AI Gateway?</Summary>

Add provider credentials to the Langfuse AI Gateway, issue gateway keys, and change each client's base URL and key. Model IDs use the form `<credential>:<model>`. Apps that rely on Portkey for providers other than OpenAI, Anthropic, or Bedrock, or for fallbacks, need those features elsewhere. See [send your first request](/docs/gateway/get-started/first-request).

</Details>

</FaqDetails>

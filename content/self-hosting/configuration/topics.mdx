# Topics

Topics runs on your existing Langfuse web and worker services, using Postgres, ClickHouse, Redis, and blob storage. Clustering runs inside the worker; the official worker image includes the required native module.

This page covers infrastructure configuration. For project setup and usage, see the [Topics guide](/docs/observability/features/topics).

## Configure model access [#model-access]

Create project or inherited organization [LLM connections](/docs/administration/llm-connection), then follow the [Topics setup steps](/docs/observability/features/topics#get-started) to select your models.

Both **web and worker** need access to the configured provider endpoints: web validates model configuration, and worker processes traces and names topics. Keep `ENCRYPTION_KEY` consistent across both services so they can read the stored credentials; see [encryption configuration](/self-hosting/configuration/encryption).

For a private model endpoint or gateway, configure the [LLM connection outbound URL allowlists](/self-hosting/configuration/hardening#outbound-url-allowlists) on both services.

### Embedding compatibility

Choose a dimension count supported by your embedding model. Langfuse accepts **64–2,048 dimensions**, with **1,024** as the default. The model must return the configured number of dimensions. See [model selection and costs](/docs/observability/features/topics#models-and-costs) before processing your first traces.

## Configure storage retention [#storage-retention]

Trace processing stages assembled transcripts in the event-upload bucket under `${LANGFUSE_S3_EVENT_UPLOAD_PREFIX}events-dispatch/trace-transcript/`. Configure a [blob storage lifecycle policy](/self-hosting/deployment/infrastructure/blobstorage) to expire objects under this prefix after three days, or set `LANGFUSE_EVENTS_DISPATCH_TRANSCRIPT_CLEANER_ENABLED=true` on the worker. The cleaner is disabled by default and requires permission to list and delete objects in the prefix.

For versioned storage or soft delete, configure lifecycle expiry for retained versions too.

<Callout type="warning">
  These temporary objects contain trace content. Trace and project deletion do
  not remove them; cleanup depends on the configured cleaner or lifecycle policy.
</Callout>

## Start processing

Start a small live map or snapshot and confirm that you can open a topic and its source traces. This exercises model access and the worker's clustering runtime.

## Tune worker load [#worker-load]

`LANGFUSE_TOPICS_TRACE_QUEUE_PROCESSING_CONCURRENCY` controls concurrent per-trace jobs per worker and queue shard (default: `20`). Lower it when provider rate limits or worker capacity require less concurrency.

Clustering consumes worker CPU and memory too. Allow headroom alongside ingestion and evaluation jobs; see [sizing and scaling](/self-hosting/configuration/scaling) for worker deployment options.

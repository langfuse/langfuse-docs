# Topics

Topics works on self-hosted Langfuse **v4.86.0 or later** with no extra environment variables. It runs on your existing web and worker services (Postgres, ClickHouse, Redis, blob storage). The official worker image includes the native clustering module for amd64 and arm64.

For project setup and usage, see the [Topics guide](/docs/observability/features/topics).

## Enable Topics [#enable-topics]

1. **Upgrade** web and worker to v4.86.0 or later.
2. **Add an LLM connection** to the project or organization ([LLM connections](/docs/administration/llm-connection)), then select the models in the [Topics setup steps](/docs/observability/features/topics#get-started). Web and worker both need network access to the provider endpoint. If you use outbound URL allowlists, [allow the endpoint](/self-hosting/configuration/hardening#outbound-url-allowlists) on both services. Both services also need the deployment's existing [`ENCRYPTION_KEY`](/self-hosting/configuration/encryption#application-level-encryption) to read the stored credentials.
3. **Expire temporary transcripts.** Topics stores trace transcripts under `events-dispatch/trace-transcript/` in the event-upload bucket (prefixed with `LANGFUSE_S3_EVENT_UPLOAD_PREFIX` if you set one). Add a [lifecycle rule](/self-hosting/deployment/infrastructure/blobstorage) that expires that path after 3 days, or set `LANGFUSE_EVENTS_DISPATCH_TRANSCRIPT_CLEANER_ENABLED=true` on the worker (it needs list and delete permissions). On versioned or soft-delete buckets, also expire noncurrent versions.

<Callout type="warning">
  These objects contain trace content. Deleting traces or projects does not remove them. Only the lifecycle rule or the cleaner does.
</Callout>

## Verify processing [#start-processing]

To check that it works, create a live map for a test workflow with 100% sampling. Send a matching trace and wait for its summary to appear. This takes about 10 minutes after the trace goes idle.

## Advanced configuration and troubleshooting [#advanced]

You only need this section if something isn't working or you want to tune load. The defaults suit most deployments.

### No traces are processed

- Topics only processes traces ingested through OpenTelemetry into the v4 events table. Make sure `LANGFUSE_MIGRATION_V4_WRITE_MODE` is not `legacy`.
- Don't set `LANGFUSE_EVENTS_DISPATCH_ENABLED=false` or `QUEUE_CONSUMER_EVENTS_DISPATCH_QUEUE_IS_ENABLED=false` on your workers. Both default to `true`. If you set either, remove it and redeploy.
- Check the map's filters and sampling rate. Together they decide which traces Topics analyzes.

### Provider rate limits or cost [#worker-load]

Each Topics job makes one summary call and one embedding call. By default, each worker runs up to **20** jobs at once. Lower the limit if your provider returns 429 errors:

| Variable                                             | Default  | Purpose                                                                            |
| ---------------------------------------------------- | -------- | ---------------------------------------------------------------------------------- |
| `LANGFUSE_TOPICS_TRACE_QUEUE_PROCESSING_CONCURRENCY` | `20`     | Topics jobs run at once, per worker and queue shard                                |
| `LANGFUSE_TOPICS_MAX_INPUT_CHARACTERS`               | `500000` | Maximum transcript characters sent per summary request (about 135k to 150k tokens) |
| `LANGFUSE_TOPICS_NIGHTLY_REFIT_HOUR_UTC`             | `4`      | UTC hour when the nightly map refit starts                                         |

Total concurrency grows with the number of worker replicas.

### Dedicated worker for dispatch (optional)

On large deployments you can run dispatch on a dedicated worker pool. Set `QUEUE_CONSUMER_EVENTS_DISPATCH_QUEUE_IS_ENABLED=false` on the other workers. You don't have to do this to keep things correct, because only one worker at a time runs the dispatcher.

### Worker resources

Clustering uses worker CPU and memory. Leave headroom next to ingestion and evaluation jobs. See [sizing and scaling](/self-hosting/configuration/scaling).

### Embedding dimensions [#embedding-compatibility]

Langfuse accepts 64 to 2,048 embedding dimensions and defaults to 1,024. Pick a value your embedding model supports. The model must return exactly that many dimensions.

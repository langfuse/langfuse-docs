# Docker Compose

This guide will walk you through deploying Langfuse locally or on a VM using Docker Compose.
We will use the [`docker-compose.yml`](https://github.com/langfuse/langfuse/blob/main/docker-compose.yml) file.
This is the simplest way to run Langfuse to give it a try.

If you would rather not run any infrastructure, use [Langfuse Cloud](/cloud): hosted by Langfuse, with a free tier and no infrastructure to run. The SDKs and integrations work identically against Langfuse Cloud and a self-hosted instance.

If you use a cloud provider like AWS, GCP, or Azure, you will need permissions to deploy virtual machines.

For high-availability and high-throughput, we recommend using Kubernetes ([deployment guide](/self-hosting/deployment/kubernetes-helm)).
The docker compose setup lacks high-availability, scaling capabilities, and backup functionality.

<Callout type="info">
  Coming from docker-compose v2? See our upgrade guide for [docker
  compose](/self-hosting/upgrade-guides/upgrade-v2-to-v3#docker-compose).
</Callout>

### Clone Langfuse Repository

Get a copy of the latest Langfuse repository:

```bash
git clone https://github.com/langfuse/langfuse.git
cd langfuse
```

### Start the application

Update the secrets in the docker-compose.yml and then run the langfuse docker compose using:

```bash
docker compose up
```

Watch the containers being started and the logs flowing in.
After about 2-3 minutes, the langfuse-web-1 container should log "Ready".
At this point you can proceed to the next step.

### Done

And you are ready to go! Open `http://localhost:3000` in your browser to access the Langfuse UI.

There is no default login. Langfuse does not ship with a built-in admin account or password. Click **Sign up** on the login page to create the first user, then create your organization and project in the UI. To pre-create the organization, project, API keys, and first user without the UI, use [headless initialization](/self-hosting/administration/headless-initialization).

### Start a new instance and SSH into it

Enter your cloud provider interface and navigate to the VM instance section.
This is EC2 on AWS, Compute Engine on GCP, and Virtual Machines on Azure.
Create a new instance.

We recommend that you use at least 4 cores and 16 GiB of memory, e.g. a t3.xlarge on AWS.
Assign a public IP address in case you want to send traces from external sources.
As observability data tends to be large in volume, choose a sufficient amount of storage, e.g. 100GiB.

The rest of this guide will assume that you have an Ubuntu OS running on your VM and are connected via SSH.

### Install Docker and Docker Compose

Install docker (see [official guide](https://docs.docker.com/engine/install/ubuntu/) as well). Setup Docker's apt repository:

```bash
# Add Docker's official GPG key:
sudo apt-get update
sudo apt-get install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
```

Install Docker packages:

```bash
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Verify installation:

```bash
sudo docker run hello-world
```

### Clone Langfuse Repository

Get a copy of the latest Langfuse repository:

```bash
git clone https://github.com/langfuse/langfuse.git

cd langfuse
```

### Update Secrets

We strongly recommend that you update the secrets in the docker-compose file.
All sensitive lines are marked with `# CHANGEME`.
Make sure to select long, random passwords for all secrets.

### Update network parameters (optional)

Only the langfuse-web container and minio must be accessible from outside the instance.
Therefore, we recommend to add a security group or firewall to your instance that restricts incoming traffic to port :3000 and :9090.
If you use the [AI Gateway](#ai-gateway), allow traffic to the TLS-terminating reverse proxy in front of it rather than to port :3031, because the gateway serves plain HTTP. Host firewalls such as ufw don't filter ports that Docker publishes, so block :3031 in the security group or [keep it off the network](#ai-gateway-public-url).

### Start the application

```bash
docker compose up
```

Watch the containers being started and the logs flowing in.
After about 2-3 minutes, the langfuse-web-1 container should log "Ready".
At this point you can proceed to the next step.

### Done

And you are ready to go! Open `http://<instance-ip>:3000` in your browser to access the Langfuse UI.

There is no default login. Langfuse does not ship with a built-in admin account or password. Click **Sign up** on the login page to create the first user, then create your organization and project in the UI. To pre-create the organization, project, API keys, and first user without the UI, use [headless initialization](/self-hosting/administration/headless-initialization).

Depending on your configuration, you might need to open an SSH tunnel to your VM to access the IP. Please refer to your cloud provider's documentation for how to do this.

## Docker log rotation

The default `docker-compose.yml` inherits the [Docker daemon's logging configuration](https://docs.docker.com/engine/logging/configure/). Docker's default `json-file` driver does not rotate logs unless configured, which can exhaust disk space. Set its [`max-size` and `max-file` options](https://docs.docker.com/engine/logging/drivers/json-file/), or keep your chosen logging backend and configure retention there. Do not rotate or truncate Docker-managed JSON log files with external tools.

After changing daemon logging defaults, restart Docker and recreate existing containers to apply them; restarting containers alone is insufficient. Plan for interruption and preserve data volumes. These settings cover container stdout/stderr, not database data volumes or ClickHouse's internal log files.

## AI Gateway [#ai-gateway]

The default `docker-compose.yml` includes the [AI Gateway](/self-hosting/configuration/ai-gateway) (beta) as the `langfuse-ai-gateway` service. It starts with the stack but stays idle until you set its two keys: `/health` returns `200`, while `/ready` and model requests return `503` (the compose file sets `LANGFUSE_AI_GATEWAY_ALLOW_MISSING_SERVICE_KEY=true`). Read the [gateway guide](/self-hosting/configuration/ai-gateway) for the requirements and concepts, then turn it on:

<Steps>

### Update an existing installation

<Callout type="warning">

`git pull` moves the checkout to the current major version. If you still run Langfuse v3, finish the [v3 to v4 upgrade](/self-hosting/upgrade/upgrade-guides/upgrade-v3-to-v4) first. Pulling and restarting a v3 installation directly can permanently delete data.

</Callout>

Checkouts from before the gateway was added need a `git pull`. If you edited `docker-compose.yml`, for example its `# CHANGEME` secrets, stash your edits first and keep your secrets when you resolve conflicts, because they must match your database volumes:

```bash
git stash && git pull && git stash pop
```

### Generate the keys

Web and the gateway share a service key and an ES256 private key that web uses to sign upload tokens. Append both to the `.env` file next to `docker-compose.yml`, once:

```bash
# Start on a new line if .env doesn't end with one.
[ -n "$(tail -c1 .env 2>/dev/null)" ] && echo >> .env
echo "LANGFUSE_AI_GATEWAY_SERVICE_KEY=$(openssl rand -hex 32)" >> .env
printf '%s\n' "LANGFUSE_AI_GATEWAY_JWT_PRIVATE_KEY='$(openssl ecparam -name prime256v1 -genkey -noout | awk '{printf "%s\\n", $0}')'" >> .env
```

The PEM key is stored on a single line, with `\n` for its line breaks. Keep `.env` private. To change the keys later, see [Rotating keys](/self-hosting/configuration/ai-gateway#rotate-keys).

### Start Langfuse

The gateway needs a Langfuse release newer than `v4.75.0`. `LANGFUSE_IMAGE_TAG` (default `4`) sets the tag of web, worker, and gateway together; `LANGFUSE_AI_GATEWAY_IMAGE_TAG` overrides the gateway's only. `--pull always` replaces older cached images behind the tag:

```bash
docker compose up -d --pull always
curl http://localhost:3031/ready
# {"status":"ready"}
```

Web counts the gateway as deployed once both keys are set; set `LANGFUSE_AI_GATEWAY_DEPLOYED=false` to hide it. Continue with [Set up Gateway as an admin](/docs/gateway/get-started/admin-setup).

</Steps>

### Port, public URL, and TLS [#ai-gateway-public-url]

The gateway listens on and publishes port `3031`. To change it, set `LANGFUSE_AI_GATEWAY_PORT` in `.env` to a port number; the port mapping, healthcheck, and default public URL follow it.

<Callout type="warning">

Web shows `http://localhost:3031` as the gateway's [public URL](/self-hosting/configuration/ai-gateway#public-url) by default, which only works on the Docker host. On a remote host, or whenever users reach Langfuse from other machines, you must set `LANGFUSE_AI_GATEWAY_PUBLIC_URL` in `.env` to the address clients use, such as `https://gateway.langfuse.example.com`.

</Callout>

The gateway serves plain HTTP. For access from other machines, put a TLS-terminating reverse proxy in front of it, configured as in [Proxy timeouts and buffering](/self-hosting/configuration/ai-gateway#timeouts), and expose only the proxy. Host firewalls such as ufw or firewalld don't filter ports that Docker publishes, so block `3031` in your cloud security group, or edit `docker-compose.yml`:

- **Proxy on the host:** bind the port to loopback with the mapping `127.0.0.1:${LANGFUSE_AI_GATEWAY_PORT:-3031}:${LANGFUSE_AI_GATEWAY_PORT:-3031}`.
- **Proxy in a container:** attach it to the Compose network, point it at `http://langfuse-ai-gateway:3031` (or your `LANGFUSE_AI_GATEWAY_PORT`), and remove the gateway's port mapping.

### Optional settings [#ai-gateway-settings]

Set these in `.env`:

- `LANGFUSE_AI_GATEWAY_CONNECTION_DRAIN_TIMEOUT_SECONDS` (`30`), `LANGFUSE_AI_GATEWAY_TELEMETRY_SHUTDOWN_TIMEOUT_SECONDS` (`20`), and `LANGFUSE_AI_GATEWAY_STOP_GRACE_PERIOD` (`60s`, keep it above the sum of the two), see [Graceful shutdown](/self-hosting/configuration/ai-gateway#graceful-shutdown).
- `LANGFUSE_AI_GATEWAY_LOG_LEVEL` (`info`).
- The web variables `LANGFUSE_AI_GATEWAY_DEPLOYED`, `LANGFUSE_AI_GATEWAY_ENABLED`, `LANGFUSE_AI_GATEWAY_ORGANIZATION_ID_ALLOWLIST`, and the [key rotation](/self-hosting/configuration/ai-gateway#rotate-keys) variables.

The gateway reaches web at `http://langfuse-web:3000`, which `.env` can't change. If web runs under a [custom base path](/self-hosting/configuration/custom-base-path), append it to `LANGFUSE_AI_GATEWAY_WEB_URL` in `docker-compose.yml`.

## Scaling

Docker compose does not support horizontal scaling without an additional Load Balancer component.
We recommend to use one of the other deployment options if your load exceeds single-instance scale or requires high availability.
To add more throughput on a docker compose setup, you can usually use a larger virtual machine, i.e. scale vertically.

## Shutdown

You can stop the containers by hitting `Ctrl+C` in the terminal.
If you started docker-compose in the background (`-d` flag), you can stop all instance using:

```bash
docker compose down
```

Adding the `-v` flag will also remove the volumes.

Ensure to stop the VM instance in your cloud provider interface to avoid unnecessary costs.

## Changing the exposed ports [#ports]

The default `docker-compose.yml` publishes three services on the host: the Langfuse UI on port `3000` (`langfuse-web`, mapping `3000:3000`), MinIO on port `9090` (mapping `9090:9000`), and the AI Gateway on port `3031` (`langfuse-ai-gateway`). If the UI or MinIO port is already taken on your machine, change the host side of the mapping (the left value) and leave the container side unchanged, for example `3001:3000` for the UI. To move the gateway, set `LANGFUSE_AI_GATEWAY_PORT` in `.env` instead, see [Port, public URL, and TLS](#ai-gateway-public-url).

When you change a port, also update the URLs that point at it:

- `NEXTAUTH_URL` must match the URL users open in the browser, for example `http://localhost:3001`. Langfuse uses it for authentication callbacks and for links in the UI and in emails.
- `LANGFUSE_S3_MEDIA_UPLOAD_ENDPOINT` on `langfuse-web` defaults to `http://localhost:9090` and must point at the new MinIO host port, because browsers upload and download media through this URL.

Ports that are bound to `127.0.0.1` (the worker on `3030`, MinIO console on `9091`, and the databases) are only reachable from the host itself and usually do not need to change.

## Troubleshooting

- Multimodal tracing is not working: This docker compose setup by default uses MinIO for blob storage which is not accessible from outside the Docker network for direct uploads. Please refer to the [blob storage guide](/self-hosting/deployment/infrastructure/blobstorage#minio-media-uploads) for more details on how to configure MinIO for media uploads.
- Make sure that the VM has enough disk space for accumulating traces.

## How to Upgrade

To upgrade Langfuse, you can stop the containers and run `docker compose up --pull always`.

For more details on upgrading, please refer to the [upgrade guide](/self-hosting/upgrade).

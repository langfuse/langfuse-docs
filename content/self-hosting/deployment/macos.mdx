# Run Langfuse locally on macOS

Run Langfuse locally on an Apple silicon Mac using Apple's `container` runtime and the [Langfuse Helm chart](/self-hosting/deployment/kubernetes-helm). The setup runs Langfuse and its data stores in a single-node Kubernetes cluster.

<Frame>
![A trace displayed in the Langfuse UI](/images/docs/observability/first-trace.png)
</Frame>

<Callout type="warning">
  This setup is intended for local evaluation. After stopping the runtime or
  restarting your Mac, you may need to recreate the cluster, which deletes its
  local data. See the [cluster lifecycle
  limitations](https://github.com/apple/container/issues/2440).
</Callout>

## Requirements

- An Apple silicon Mac running macOS 26 or later.
- [Apple `container` 1.7.1](https://github.com/apple/container/releases/tag/1.7.1).
- [kubectl](https://kubernetes.io/docs/tasks/tools/install-kubectl-macos/) 1.34–1.36, compatible with the cluster's Kubernetes 1.35 version.
- [Helm](https://helm.sh/docs/intro/install/) 3.17 or later.

## Create the cluster

Start the runtime. On first use, accept its recommended Linux kernel download:

```bash
container system start
```

Allow the macOS **Local Network** permission for `container-runti` / `container-runtime-linux`. If needed, enable it under **System Settings → Privacy & Security → Local Network**.

This example allocates 6 CPUs and 16 GiB of memory to the cluster. Leave enough memory available for macOS and other applications, and disk space for container images and trace data.

Use a separate kubeconfig file to preserve your existing Kubernetes context. Run the setup and installation commands in the same terminal:

```bash
mkdir -p "$HOME/.kube"
export KUBECONFIG="$HOME/.kube/langfuse-local"

container cluster create --name langfuse-local --cpus 6 --memory 16g
kubectl --context langfuse-local get nodes
```

Wait for the node to show `Ready`.

## Install the prerequisites

Install [Local Path Provisioner](https://github.com/rancher/local-path-provisioner) for persistent storage, followed by [cert-manager](https://cert-manager.io/docs/installation/helm/) and the [ClickHouse operator](/self-hosting/deployment/infrastructure/clickhouse#clickhouse-kubernetes-operator). These dependencies must be ready before installing the Langfuse chart.

```bash
kubectl --context langfuse-local apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.37/deploy/local-path-storage.yaml
kubectl --context langfuse-local -n local-path-storage rollout status deployment/local-path-provisioner --timeout=180s

helm --kube-context langfuse-local upgrade --install cert-manager \
  oci://quay.io/jetstack/charts/cert-manager \
  --version v1.20.2 \
  --namespace cert-manager --create-namespace \
  --set crds.enabled=true --wait --timeout 5m

kubectl --context langfuse-local wait --for=condition=Established \
  crd/certificates.cert-manager.io crd/issuers.cert-manager.io --timeout=120s

helm --kube-context langfuse-local upgrade --install clickhouse-operator \
  oci://ghcr.io/clickhouse/clickhouse-operator-helm \
  --version 0.0.8 \
  --namespace clickhouse-operator --create-namespace \
  --wait --timeout 5m

kubectl --context langfuse-local wait --for=condition=Established \
  crd/clickhouseclusters.clickhouse.com crd/keeperclusters.clickhouse.com --timeout=120s
```

## Configure Langfuse

Save this as `values-local.yaml`. It uses one replica per service, keeps ClickHouse Keeper enabled, and stores data inside the node VM. Ingress and the optional AI Gateway are disabled.

```yaml filename="values-local.yaml"
langfuse:
  replicas: 1
  nextauth:
    url: http://localhost:3000
  ingress:
    enabled: false
  gateway:
    enabled: false
  additionalEnv:
    - name: LANGFUSE_S3_MEDIA_UPLOAD_INTERNAL_ENDPOINT
      value: http://langfuse-s3-all-in-one:8333
    - name: LANGFUSE_S3_BATCH_EXPORT_EXTERNAL_ENDPOINT
      value: http://localhost:8333

postgresql:
  storage:
    requestedSize: 5Gi
    className: local-path

redis:
  dataStorage:
    enabled: true
    requestedSize: 1Gi
    className: local-path

clickhouse:
  cluster:
    replicas: 1
    storage:
      size: 20Gi
      className: local-path
  keeper:
    enabled: true
    replicas: 1
    storage:
      size: 1Gi
      className: local-path

s3:
  mediaUpload:
    endpoint: http://localhost:8333
  allInOne:
    data:
      type: persistentVolumeClaim
      size: 10Gi
      storageClass: local-path
```

The browser uses `localhost:8333` for media and batch downloads; server-side storage requests use the internal SeaweedFS service. Keep these endpoints separate. See [blob storage configuration](/self-hosting/deployment/infrastructure/blobstorage) for details.

## Install Langfuse

Use the release name `langfuse`, matching the service names in the values above. Helm generates the application and datastore secrets on first installation and retains them across upgrades.

```bash
helm --kube-context langfuse-local upgrade --install langfuse \
  oci://ghcr.io/langfuse/langfuse-k8s/charts/langfuse \
  --version 2.2.3 \
  --namespace langfuse --create-namespace \
  -f "values-local.yaml" --wait --timeout 20m

kubectl --context langfuse-local -n langfuse get pods,pvc
```

Expect the web, worker, and data services to become ready, with five persistent volume claims showing `Bound`. Initial restarts can occur while PostgreSQL initializes and Keeper becomes available.

## Open Langfuse

Run each port-forward in its own terminal and leave both running:

```bash
kubectl --kubeconfig "$HOME/.kube/langfuse-local" --context langfuse-local \
  -n langfuse port-forward --address 127.0.0.1 svc/langfuse-web 3000:3000
```

```bash
kubectl --kubeconfig "$HOME/.kube/langfuse-local" --context langfuse-local \
  -n langfuse port-forward --address 127.0.0.1 svc/langfuse-s3-all-in-one 8333:8333
```

Open `http://localhost:3000`, click **Sign up**, and create an organization and project. There is no default login. [Headless initialization](/self-hosting/administration/headless-initialization) is also available.

To start sending traces, follow the [SDK quickstart](/docs/observability/sdk/overview) with `LANGFUSE_BASE_URL=http://localhost:3000` and your project's API keys.

<Callout type="info">
  These endpoints are reachable only from this Mac. Restart a port-forward if its
  selected pod is replaced, for example after a Helm upgrade.
</Callout>

## Shutdown

Press **Ctrl+C** in both port-forward terminals to close browser and SDK access. This leaves the cluster running. To delete the cluster and its stored data:

```bash
container cluster delete --name langfuse-local
```

## Troubleshooting

- **Connection reset or `No route to host`:** check that the runtime has the macOS Local Network permission described above.
- **Helm reports `docker-credential-desktop` is missing:** an existing Docker configuration may reference an uninstalled credential helper. Retry the public chart commands with an isolated, empty Docker configuration in the installation terminal:

  ```bash
  export DOCKER_CONFIG="$(mktemp -d)"
  ```

  Run `unset DOCKER_CONFIG` when finished to restore the normal configuration lookup.

- **A service remains unready:** inspect it with `kubectl --context langfuse-local -n langfuse describe pod <pod-name>` and `kubectl --context langfuse-local -n langfuse logs <pod-name>` from the installation terminal.

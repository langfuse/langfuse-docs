You can deploy Langfuse v4 on [Railway](https://railway.com/) via a prebuilt template.
The template creates separate Railway services for the Langfuse web service, worker, and each data store.
See the [architecture overview](/self-hosting#architecture) for more details.

<Callout type="warning">
  After deployment, verify that PostgreSQL and ClickHouse use UTC. See the
  [timezone requirements and verification
  steps](/faq/all/self-hosting-timezone-errors).
</Callout>

## Deploy

Use the following button to deploy the Langfuse v4 template on Railway:

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/langfuse-v4-llm-observability?referralCode=513qqz)

The template creates these resources:

- Langfuse v4 web (`langfuse/langfuse:4`, public domain) and worker (`langfuse/langfuse-worker:4`, private) services
- A Railway PostgreSQL 18 database
- A Railway Redis instance with a persistent volume
- A single-node ClickHouse 26.3 service with a persistent volume
- A Railway storage bucket used as S3-compatible blob storage for event uploads, media, and batch exports

The template sets `CLICKHOUSE_CLUSTER_ENABLED=false` for the single-node ClickHouse, and configures ClickHouse to listen on IPv6 because Railway's private network is IPv6-only.
The first boot runs the PostgreSQL and ClickHouse migrations before the web service becomes healthy, which can take several minutes.

Select resource limits that match your expected workload, and configure backups for the PostgreSQL and ClickHouse volumes before you send production traffic.

For more details, see the [template repository](https://github.com/Amritasha/langfuse-railway).

### Langfuse v3

The previous Langfuse v3 template remains available: [Deploy Langfuse v3 on Railway](https://railway.com/deploy/exma_H?referralCode=513qqz).
New deployments should use v4. To upgrade an existing v3 deployment, follow the [v3 to v4 upgrade guide](/self-hosting/upgrade/upgrade-guides/upgrade-v3-to-v4).
